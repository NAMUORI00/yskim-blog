인공지능 모델이 계산할 때 곱하는 숫자인 가중치를 −1, 0, +1 세 가지 값으로만 제한해도 모델 파일이 곧바로 원소당 1.58비트로 줄어들지는 않는다. 계산 수식에서 값의 종류를 몇 가지로 줄이는지와 그 값을 실제 메모리에 어떤 자료형으로 담아 연산하는지는 별개의 구현 영역이기 때문이다.


수치 정밀도와 소수를 제한된 값으로 바꾸는 양자화의 기본 원리는 앞선 기초편에서 다뤘다. 이번에는 `bitnet-llama3` 저장소의 `BitLinear` 코드를 읽으며 가중치가 학습 중에 어떻게 계산되고 추론용 레이어로 변환될 때 무엇이 바뀌는지 확인했다. 가중치 네 개짜리 작은 예제를 실제 코드의 수식에 대입해 표현값과 저장 형식, 실행 함수가 각각 어떻게 연결되는지 따라간다. 본문에 연결한 소스 코드는 비공개 저장소여서 접근 권한이 필요하다.


## 삼진 가중치와 1.58비트의 의미


수식의 상태 수와 실제 메모리 크기가 왜 다른지 이해하려면 먼저 1.58비트라는 숫자의 출처를 짚어야 한다. 2024년 발표된 [BitNet b1.58 논문](https://arxiv.org/abs/2402.17764)은 모델 가중치를 −1, 0, +1로만 제한하는 **삼진 가중치**(ternary weight)를 소개했다. 정보이론에서 세 가지 상태를 구분하는 데 필요한 최소 정보량은 $\log_2 3$, 약 1.585비트다. 논문 제목의 1.58비트는 이 이론적 정보량에서 나온 숫자다.


하지만 컴퓨터 메모리는 8비트 묶음인 바이트 단위로 주소를 다루므로 원소 하나를 정확히 1.585비트 크기로 저장할 수는 없다. 원소마다 2비트를 배정하거나 여러 원소를 한 바이트 안에 묶어 넣을 수도 있고, 소수를 담는 다차원 배열인 부동소수점 텐서에 값만 세 종류로 담아 둘 수도 있다. 이 가운데 어떤 저장 방식을 쓰느냐에 따라 실제 메모리 사용량과 파일 크기는 크게 달라진다. 여기에 원래 값의 크기를 복원하기 위한 비례 상수인 **스케일**(scale) 같은 부가 정보도 함께 저장해야 한다.


따라서 저장소 이름에 BitNet이 들어가더라도 논문의 메모리 절감이나 속도 향상 수치를 그대로 대입하기는 어렵다. 가중치를 세 값으로 제한하는 수식이 같더라도 학습 조건과 저장 포맷이 다를 수 있다. 저비트 연산을 직접 처리하는 실행 함수인 **커널**(kernel)까지 갖춰져야 논문과 같은 출발선에서 품질과 효율을 비교할 수 있다. 이번 작업에서는 논문 성능을 재현하는 실험 대신, 저장소의 `BitLinear` 코드가 학습과 추론에서 삼진 가중치를 실제로 어떻게 다루는지 확인했다.


## 가중치와 활성값 양자화 계산


삼진 가중치와 스케일이 실제 코드에서 어떻게 계산되는지는 [`weight_quant`](https://github.com/NAMUORI00/bitnet-llama3/blob/6b95497250050702ed89f6d41da40e0c150d5150/src/llama3/bitlinear.py) 함수의 수식에서 확인할 수 있다. 이 함수는 가중치 텐서에서 절대값의 평균(absmean)을 구하고 그 역수를 스케일로 삼아 삼진 양자화를 수행한다. 각 가중치에 스케일을 곱한 뒤 반올림(`round`)하고, 값을 −1과 1 사이로 제한(`clamp`)한 다음 다시 스케일로 나누어 원래 수치 범위로 되돌린다.


설명용 가중치 네 개를 `[−0.8, −0.1, 0.2, 0.9]`로 두고 이 수식에 차례대로 대입해 본다. 네 값의 절대값 평균은 `0.5`이고, 그 역수인 스케일은 `2`다. 가중치에 스케일 `2`를 곱하면 `[−1.6, −0.2, 0.4, 1.8]`이 되고, 반올림과 범위 제한을 거치면 `[−1, 0, 0, 1]`로 바뀐다. 함수가 최종적으로 반환하는 값은 이를 다시 스케일 `2`로 나눈 `[−0.5, 0, 0, 0.5]`다. 결과 텐서에 세 종류의 값만 남는다는 설명은 맞지만, 반환값이 정수 `−1, 0, 1` 그대로라고 생각하면 마지막 나눗셈 단계를 놓치게 된다.

그림 1. 가중치 네 개에 weight_quant 함수를 적용한 단계별 값 변화다. 저정밀도 가중치 계산 수식을 바탕으로 직접 계산해 구성했다.


레이어를 통과하는 입력값인 활성값(activation)은 가중치와 다른 기준으로 양자화한다. `activation_quant` 함수는 마지막 차원에서 최대 절대값(maxabs)을 찾아 그 값이 127에 맞도록 스케일을 곱한다. 그 뒤 반올림과 범위 제한을 거친 다음 다시 스케일로 나누어 원래 범위로 되돌린다. 코드 주석에는 절대값 평균을 뜻하는 `absmean`이라는 표현이 섞여 있지만 실제로 실행되는 수식은 최대 절대값 기준이다. 이처럼 값의 범위를 일정한 기준으로 맞추는 정규화 방식은 가중치가 절대값 평균 기준, 활성값이 최대 절대값 기준으로 서로 다르다.


## 학습 중 가중치 보간과 STE 경로


학습할 때 실행되는 `BitLinear.forward`는 앞 절의 양자화 함수를 호출하되 그 결과를 곧바로 그대로 쓰지 않는다. 먼저 입력에 정규화(`layer_norm`)를 적용하고 양자화 계산을 임시로 32비트 부동소수점(`float32`)에서 수행한다. 그다음 원래 가중치에 양자화 차이의 일부만 더하는 보간(interpolation)을 거친다. 가중치 쪽 계산을 간단히 줄여 쓰면 다음과 같다.


```python
w_used = w + lambda_ * (quantized_w - w).detach()
```


모델은 입력에서 출력을 계산하는 순전파를 거친 뒤, 오차를 줄이는 방향인 기울기(gradient)를 거꾸로 전달하는 역전파로 가중치를 고친다. 그런데 반올림 연산은 값이 계단처럼 끊어져 미분값이 대부분 0이 되므로 그대로는 역전파 기울기를 전달하기 어렵다. 위 코드에서 `.detach()`는 괄호 안의 차이 `(quantized_w - w)`를 역전파 계산 경로에서 떼어 놓는다. 그 결과 순전파에서는 양자화 영향이 반영된 `w_used`를 쓰고, 역전파에서는 양자화 함수를 건너뛰어 원래 가중치 `w`로 기울기를 그대로 흘려보낸다. 이처럼 미분하기 어려운 양자화 연산을 역전파 때 항등 함수처럼 그대로 통과시키는 방식을 **STE**(Straight-Through Estimator)라고 한다. 물론 코드에 STE가 들어 있다는 점만 확인했을 뿐, 이 수식만으로 실제 학습의 수렴 안정성까지 판단할 수는 없다.


![순전파에서는 detach된 양자화 차이를 lambda_로 보간해 w_used를 만들고 역전파에서는 원래 가중치 w로 기울기를 직접 전달하는 구조도](/images/notion/tech-05-04/image-2.png)


그림 2. BitLinear.forward의 가중치 보간 수식을 바탕으로 구성한 순전파 보간과 역전파 STE 기울기 전달 경로다.


보간 계수인 `lambda_`는 양자화 반영 강도를 조절한다. `lambda_`가 `1`일 때 앞선 예제의 가중치 `[−0.8, −0.1, 0.2, 0.9]`는 완전히 양자화된 `[−0.5, 0, 0, 0.5]`로 바뀐다. 반면 `lambda_`가 `0.5`라면 원래 값과 양자화 값의 중간을 쓰므로 `−0.8`은 `−0.65`로, `0.2`는 `0.1`로 바뀐다. 이처럼 학습 중간 단계에는 세 종류보다 많은 값이 남으며, 학습이 진행될수록 양자화 영향을 점진적으로 키운다. 모든 학습 단계에서 가중치가 이미 삼진 상태라고 생각하면 이 보간 과정을 놓치게 된다.


현재 학습 단계(스텝)는 외부에서 전달받고, 진행 단계에 따라 값을 조정하는 스케줄러 함수가 그에 맞는 `lambda_` 값을 계산한다. 따라서 실제 학습을 검증할 때는 스케줄러 함수의 존재만 볼 것이 아니다. 스텝 갱신이 각 레이어까지 제대로 전달되는지와 학습 종료 시점의 최종 `lambda_` 값이 얼마인지를 함께 확인해야 한다. 학습을 끝내고 저장한 모델 파일인 체크포인트를 추론용으로 변환해 가중치를 강제로 세 값으로 고정했을 때 출력이 얼마나 달라지는지도 별도로 비교할 항목이다.


## 추론용 변환과 비트 패킹


학습을 마친 레이어를 추론에 쓰려면 같은 파일의 `BitLinearInference.from_bit_linear` 함수로 변환해야 한다. 이 함수는 가중치를 반올림과 범위 제한으로 `−1, 0, 1` 세 값으로만 제한하고 `w_scale`을 별도 변수로 저장한다. 하지만 `round`와 `clamp` 연산은 텐서 안의 값 종류만 바꿀 뿐, 텐서 자료형 자체를 작은 비트열로 압축하지는 않는다. 여러 개의 저비트 정수를 하나의 바이트나 정수형 변수 안에 빈틈없이 묶어 담는 작업을 **비트 패킹**(bit packing)이라고 한다. 변환된 `weight`에 `w_quant`를 대입하는 코드 경로에는 이 비트 패킹이 없다.


추론 시 실행되는 `BitLinearInference.forward`도 부동소수점 행렬 곱셈인 `F.linear`를 호출한 뒤 따로 저장한 스케일을 복원한다. 전용 저비트 커널을 쓰지 않는다는 코드 주석과 실제 함수 호출이 일치했다.


![학습용 부동소수점 가중치가 반올림과 범위 제한을 거쳐 부동소수점 텐서와 별도 w_scale로 나뉘고 일반 F.linear로 연산되는 흐름과 미구현된 비트 패킹 경로 비교도](/images/notion/tech-05-04/image-3.png)


그림 3. BitLinearInference 코드를 바탕으로 직접 구성한 추론용 변환과 연산 경로다. 점선은 비트 패킹과 전용 커널을 적용할 때 추가로 필요한 단계다.


예를 들어 1,000개의 가중치를 원소당 2바이트인 `float16` 텐서로 유지하면 데이터 부분만 2,000바이트가 된다. 세 가지 상태의 이상적인 정보량으로 계산한 약 198바이트와 비교하면, 텐서 자료형이 그대로여서 메모리 크기도 줄어들지 않은 것이다. 이 계산은 스케일 변수나 파일 머리말(헤더), 주소를 일정 단위로 맞추는 메모리 정렬(alignment)을 포함하지 않은 순수 가중치 데이터 크기다. 따라서 실제 체크포인트 파일 크기를 예측한 값과는 구분해 보아야 한다.


## 추론 변환 검증과 편향 누락


추론용 레이어의 내부 동작을 확인했으니, 이제 모델 전체를 추론 모드로 바꿀 때 확인할 조건을 짚어 본다. [모델 추론 실행 스크립트](https://github.com/NAMUORI00/bitnet-llama3/blob/6b95497250050702ed89f6d41da40e0c150d5150/src/llama3/run_inference.py)는 모델을 불러온 뒤 `convert_to_inference_mode` 함수를 호출한다. 이 함수는 모델 안의 `BitLinear` 인스턴스를 찾아 `BitLinearInference`로 바꾼다. 그런데 실행 로그 문구만으로는 실제로 몇 개의 레이어가 변환됐는지 알기 어렵다. 변환 대상 목록과 함수의 반환 결과, 변환 뒤 모델 안에 있는 레이어의 자료형을 함께 확인하는 편이 정확하다.


코드를 읽으며 변환 전후 동작에서 확인할 작은 항목도 하나 찾았다. 변환 함수인 `from_bit_linear`는 원본 레이어에 행렬 곱셈 뒤 더하는 상수항인 편향(`bias`)이 있으면 추론 레이어로 복사한다. 하지만 정작 추론 `forward`의 `F.linear` 호출에는 복사해 둔 `bias`를 인자로 전달하지 않는다. `bias`를 쓰지 않는 레이어에서는 이 차이가 드러나지 않지만, `bias`가 있는 레이어를 지원하는지 판단하려면 변환 전후의 출력을 직접 비교해야 한다. 이번에는 코드에서 대조해야 할 입력과 텐서의 차원 크기(형상) 조건을 먼저 정리해 두었다.

그림 4. BitLinearInference 변환 과정에서 복사된 bias가 추론 시 F.linear 호출 인자에서 빠지는 코드 구조도다.


## 결론


`bitnet-llama3`의 `BitLinear` 코드를 통해 삼진 가중치와 활성값의 양자화 수식, 학습 중 `lambda_` 보간과 STE 경로를 확인했다. 추론용 `BitLinearInference`는 가중치를 세 값과 `w_scale`로 나누지만, 비트 패킹과 전용 커널 없이 부동소수점 텐서와 `F.linear`를 그대로 쓴다. 결국 값을 적은 비트로 표현하는 수학적 원리와 실제 메모리 절감 및 속도 개선 사이에는 비트 패킹과 전용 커널이라는 구현 단계가 놓여 있다. 부동소수점 연산으로 양자화를 흉내 내는 현재 코드와 패킹된 데이터에 저비트 커널을 적용하는 단계를 구분해야 현재 구현의 위치를 정확히 파악할 수 있다.


이번 작업에서는 코드의 수식과 변환 경로만 확인했으며, 실제 학습의 수렴 안정성이나 학습 종료 시점의 최종 `lambda_` 값은 아직 검증하지 않았다. 추론 변환에서 실제로 바뀐 레이어 수와 자료형, 복사된 `bias`가 `F.linear` 인자에서 빠져 생기는 변환 전후의 출력 차이도 실행해 확인해야 할 항목이다. 이 구현을 가중치 표현 제한 실험의 출발점으로 삼더라도 변환 전후의 출력 일치 여부와 레이어 자료형부터 먼저 대조해야 한다. 그 뒤에 파일 크기와 최고 메모리 사용량, 토큰 생성 속도, 답변 품질을 각각 따로 측정하는 순서가 적절하다. 이어지는 모델 학습 글에서는 레이어 내부 활성값을 읽는 탐침 모델인 프로브(probe)로 내부 표현에서 무엇을 측정하고 어디까지 해석할 수 있는지 다룬다.
