분산 학습 구성을 이해하기 위해 원본 Nanotron의 포크에서 배치와 병렬화 설정을 확인했다. 여러 GPU에 데이터, 텐서, 레이어를 나누는 방식에 따라 전역 배치와 업데이트 조건이 어떻게 달라지는지 정리했다.


## 구현과 확인 과정


nanotron의 설정과 학습 루프를 읽으며 GPU 수와 배치 크기가 어떻게 연결되는지 따라가 봤다. GPU 여덟 개에 데이터를 나누거나 모델의 연산, 레이어를 분할할 수 있으며, 표본 처리량은 선택한 병렬화 방식에 따라 달라진다.


이 저장소는 Hugging Face Nanotron의 포크다. NAMUORI00/nanotron에서 확인한 설정을 기준으로, 병렬화 방식마다 나눠 갖는 대상과 학습 루프의 배치 계산을 함께 정리했다.


원본 Nanotron의 분산 학습 기능을 해당 포크 커밋에서 읽고 정리했다. 배치, 손실, 역전파를 알고 있다면 데이터 병렬, 텐서 병렬, 파이프라인 병렬의 차이를 먼저 읽고 이어 오면 된다.


## 데이터, 텐서, 파이프라인 병렬 구성


2026-09-15 확인한 [원본 Nanotron](https://github.com/huggingface/nanotron)은 DP, TP, PP를 함께 사용하는 학습 구성을 제공한다. DP는 모델의 논리적 복제본들이 서로 다른 데이터를 처리하는 방식이고, TP는 한 레이어의 텐서 연산을 나누며, PP는 모델의 앞뒤 레이어를 서로 다른 단계에 배치한다.


예를 들어 DP=2, PP=2, TP=2인 단순한 구성은 여덟 GPU를 사용할 수 있다. 이 중 서로 다른 데이터 묶음을 병렬로 받는 논리적 복제본은 두 개이고, 각 복제본 안의 나머지 분할은 같은 표본의 모델 계산을 나누는 데 쓰인다. 이 예에서는 전문가 병렬과 문맥 병렬 등 추가 축은 제외했다.


![06-03-01.png](/images/notion/tech-06-03/image-1.png)


그림 1. DP=2, PP=2, TP=2를 이해하기 위한 논리적 배치 예. 출처: Nanotron의 병렬 축 구분을 바탕으로 직접 구성. GPU 번호는 논리적 배치를 설명하기 위한 표기다.


어떤 분할을 늘릴지는 메모리와 통신 조건에 따라 달라진다. 모델 자체가 한 GPU에 들어가지 않으면 TP나 PP를 검토할 이유가 생기고, 모델이 들어가면서 더 많은 표본을 처리하려면 DP를 고려할 수 있다. 다만 통신과 대기 시간이 따라오므로 GPU 수가 늘어난 비율만큼 학습 시간이 줄어든다고 가정하지는 않았다.


## 데이터 병렬 수와 전역 배치 계산


[학습 반복 처리](https://github.com/NAMUORI00/nanotron/blob/9a542e794670a8c0d0232ed34098942aefe0079f/src/nanotron/trainer.py)에서 전역 배치는 다음 세 항목의 곱으로 계산된다.


```plain text
global_batch_size
  = micro_batch_size
  × batch_accumulation_per_replica
  × 데이터 병렬 그룹 크기
```


마이크로 배치가 2, 복제본당 누적 횟수가 4, DP가 2인 예에서 업데이트 하나에 해당하는 전역 배치는 16이다. 여기에 TP와 PP를 다시 곱해 64로 세면, 같은 표본이 모델의 여러 부분을 지나가는 것을 새 표본으로 중복 집계하게 된다.


고정 길이 1,024토큰으로 처리한다면 16×1,024=16,384개의 토큰 위치를 다룬다는 계산도 가능하다. 다만 패딩, 손실 마스킹, 패킹 방식에 따라 이 숫자와 유효 학습 토큰 수는 달라질 수 있다. 저장소의 처리량 계산은 전역 배치와 sequence_length를 사용하고 있어, 결과를 읽을 때도 이 정의를 기준으로 삼았다.


GPU 수를 바꾸며 배치도 함께 바꾸면 실행 속도뿐 아니라 최적화 조건도 달라진다. 같은 실험을 더 빨리 수행했는지 비교하려면 학습률, 업데이트 횟수, 전체 소비 토큰도 맞아야 한다. 장치 수와 배치 크기를 별도 항목으로 보는 이유가 여기에 있었다.


## 순전파와 역전파의 스케줄 구성


[ParallelismArgs](https://github.com/NAMUORI00/nanotron/blob/9a542e794670a8c0d0232ed34098942aefe0079f/src/nanotron/config/parallelism_config.py)는 파이프라인 엔진과 TP 통신 모드를 따로 둔다.


pp_engine을 생략하면 AllForwardAllBackward를 선택하고, tp_mode 기본값은 ALL_REDUCE다. 여러 방식을 지원한다는 점과 특정 실행에서 적용되는 기본값은 구분해 읽었다.


[AllForwardAllBackwardPipelineEngine](https://github.com/NAMUORI00/nanotron/blob/9a542e794670a8c0d0232ed34098942aefe0079f/src/nanotron/parallel/pipeline_parallel/engine.py)은 마이크로 배치의 순전파를 모두 먼저 수행하고, 역전파에 필요한 활성값을 상태에 보관한 뒤 역전파를 진행하는 구조였다.


같은 파일에 1F1B 엔진도 있었다. 준비 구간 뒤 순전파와 역전파를 번갈아 배치하고, 마지막에 남은 역전파를 마무리하는 흐름이다.


1F1B에서는 역전파를 기다리는 활성값을 줄일 여지가 있다. 다만 실제 이점은 단계 수, 마이크로 배치 수, 통신과 계산 시간에 영향을 받는다. 여기서 확인한 범위는 스케줄 구현이며 특정 GPU의 메모리 절감량은 측정하지 않았다. 작은 예제로 엔진별 업데이트 결과를 대조하는 작업이 남아 있다.

## 체크포인트의 저장 항목


학습 루프는 마이크로 배치를 처리한 뒤 기울기 동기화와 클리핑을 거쳐 optimizer.step, zero_grad를 호출한다. 다시 시작하려면 가중치 외에도 이 업데이트가 어디까지 진행됐는지 알아야 한다.


[학습 상태 저장](https://github.com/NAMUORI00/nanotron/blob/9a542e794670a8c0d0232ed34098942aefe0079f/src/nanotron/serialize/main.py)은 설정, 모델, 옵티마이저, 학습률 스케줄러, 학습 메타데이터의 저장 경로를 나눈다.


저장 옵션에 따라 포함되는 항목이 달라지므로, 체크포인트에 어떤 상태가 들어 있는지 확인해야 재개 조건을 판단할 수 있다.


코드에서 확인한 저장 항목을 바탕으로 재개 실험의 비교 기준도 정리했다. 저장 후 복원한 첫 업데이트와 중단 없이 진행한 실행의 손실, 소비 표본 수, 학습률이 그 기준이다. 병렬 배치를 바꾼 재개는 저장된 분할 정보와 복원 경로를 추가로 확인할 부분으로 남았다. 다음 강화학습 글은 환경에서 모은 경험과 보상의 기록 단위로 이어진다.


## 작업을 정리하며


장치 수와 배치 크기를 함께 바꾸면 실행 속도와 학습 조건이 동시에 변한다. 같은 실험을 비교하려면 학습률, 업데이트 횟수, 소비 토큰을 맞춰야 한다. 자원 설정을 실험 조건의 일부로 기록하는 습관이 중요하다.
