강화학습은 **에이전트**(agent)가 환경과 상호작용하며 보상을 높이는 행동 규칙을 배우는 과정이다. 출발부터 종료까지 한 번의 시도를 에피소드라고 부르는데, 학습 중 에피소드 보상이 올라가도 평가에서 같은 점수가 나온다고 보장하기 어렵다. 학습 단계에서는 새로운 행동을 시험하는 **탐험**(exploration)이 섞이고 신경망 가중치도 매 스텝 바뀌기 때문이다. 반면 평가 단계에서는 가중치를 고정하고 탐험을 끈 상태에서 학습된 행동 규칙인 정책의 성능을 측정한다.


학습 점수와 평가 점수가 달라지는 조건을 확인하려고 `ReinforcementLearningLab` 저장소(`aa968aee` 커밋)의 코드를 읽었다. 이 저장소는 정해진 선택지 중 하나를 고르는 이산 행동 에이전트인 DQN과, 연속된 숫자로 행동을 출력하는 DDPG를 비교하는 실습 코드다. 앞선 글의 상태, 행동, 보상, 정책 개념에 이어, 두 에이전트의 행동 선택과 환경 설정, 종료 신호, 실행 스크립트를 차례로 짚어 본다.


## 학습과 평가의 행동 선택


학습과 평가의 차이는 에이전트가 현재 상태에서 행동을 고르는 함수에서 먼저 드러난다. [`DQNAgent.select_action`](https://github.com/NAMUORI00/ReinforcementLearningLab/blob/aa968aee4cf6776e4f33aff6b776c0863b622816/src/agents/dqn_agent.py)은 `epsilon` 확률로 무작위 행동을 고르고, 나머지 확률로는 **Q값**이 가장 큰 행동을 선택한다. 여기서 Q값은 당장 한 스텝에서 받는 보상이 아니라, 그 행동을 한 뒤 앞으로 받을 누적 보상의 기댓값을 추정한 값이다. 함수를 호출할 때 `deterministic=True`를 넘기면 무작위 선택 분기를 건너뛰고 항상 Q값이 최대인 행동만 고른다.


연속 행동을 다루는 [`DDPGAgent.select_action`](https://github.com/NAMUORI00/ReinforcementLearningLab/blob/aa968aee4cf6776e4f33aff6b776c0863b622816/src/agents/ddpg_agent.py)은 행동을 계산하는 액터 네트워크로 연속된 행동 값을 직접 출력한다. 학습 중에는 `add_noise=True`를 넘겨 액터가 출력한 값에 탐험 노이즈를 더한다. 그다음 환경이 허용하는 행동 범위 안으로 값을 자르는 클리핑(clipping)을 거쳐 최종 행동을 내보낸다. 반대로 평가에서는 `add_noise=False`로 호출해 노이즈를 끄도록 인터페이스가 나뉘어 있다.


![현재 상태에서 DQN은 deterministic=True일 때 무작위 탐색을 건너뛰어 Q값 최대 행동을 고르고, DDPG는 add_noise=False일 때 노이즈 없이 액터 연속 행동을 출력하는 비교 순서도](/images/notion/tech-06-04/image-1.png)


그림 1. DQN과 DDPG의 행동 선택 함수에서 평가 시 탐험을 끄는 분기 구조(출처: DQN과 DDPG 행동 선택 코드를 바탕으로 직접 구성).


이처럼 학습 중 기록되는 에피소드 보상은 탐험의 무작위성과 매 스텝 갱신되는 정책이 함께 만든 결과다. 현재 정책 자체의 성능만 따로 읽으려면 가중치를 고정하고 탐험을 끈 상태에서 평가 보상을 측정해야 한다. 다만 탐험을 끄더라도 환경의 초기 상태나 내부 난수까지 저절로 고정되지는 않는다. 에피소드 한 번의 결과만으로 정책을 판단하지 않으려면 여러 평가 에피소드를 실행해 보상의 분포를 함께 기록해야 한다.


## 환경 래퍼와 보상 스케일


행동 선택에서 탐험을 끄더라도, 환경 바깥을 감싸 입출력을 바꾸는 **래퍼**(wrapper) 설정에 따라 기록되는 보상 수치가 달라진다. 기본 환경 이름부터 DQN은 `CartPole`이고 DDPG는 `Pendulum`으로 서로 다르다. DDPG 환경을 만드는 [`create_ddpg_env`](https://github.com/NAMUORI00/ReinforcementLearningLab/blob/aa968aee4cf6776e4f33aff6b776c0863b622816/src/environments/wrappers.py)를 보면 환경 바깥에 두 가지 래퍼가 붙어 있다. 먼저 `ActionWrapper`는 에이전트가 `-1`부터 `1` 사이로 출력한 연속 행동을 실제 환경의 행동 범위로 변환한다. 이어서 `RewardScaleWrapper`는 환경이 반환하는 보상에 `0.1`을 곱해 크기를 줄인다. 예를 들어 원래 환경에서 한 에피소드 동안 받은 보상 합계가 `-800`이라면 `RewardScaleWrapper`를 거친 보상 합계는 `-80`이 된다. 반면 기본 DQN 환경을 만드는 경로에는 이러한 보상 스케일 변환이 없다.


![DDPG 에이전트의 -1에서 1 사이 행동이 ActionWrapper를 거쳐 Pendulum 환경으로 들어가고, 환경의 원래 보상 -800이 RewardScaleWrapper를 거쳐 -80으로 변환되는 흐름도](/images/notion/tech-06-04/image-2.png)


그림 2. create_ddpg_env에서 연속 행동 범위를 맞추고 원래 보상에 0.1을 곱해 학습용 보상으로 바꾸는 래퍼 흐름도.


이처럼 원래 환경의 보상과 에이전트가 학습에 쓰는 보상은 서로 다른 척도다. 학습률이나 손실 함수의 수치 범위에 맞추려고 학습 보상 스케일을 조정하더라도, 점수를 비교하려면 스케일과 평가 조건을 함께 맞춰야 한다. 평가에서도 같은 래퍼를 거친 값을 쓸지, 결과 그래프에 어떤 단위를 표시할지는 따로 정해야 한다. 래퍼 적용 여부가 결과 파일에 함께 남아 있지 않으면 나중에 그래프에 적힌 보상 수치의 의미를 되짚기 어렵다.


## 에피소드 종료와 시간 제한의 분리


보상 스케일에 더해 에피소드가 끝나는 신호를 어떻게 처리하는지도 학습 목표값을 바꾼다. 환경은 매 스텝을 실행한 뒤 에피소드가 끝난 이유를 두 가지 신호로 나누어 반환한다. 환경 규칙에 따라 에피소드가 완전히 끝난 상태는 `terminated`이고, 외부에서 정한 최대 스텝 수에 걸려 중단된 상태는 `truncated`다. 그런데 이 저장소의 학습과 평가 루프는 `terminated`와 `truncated`를 `OR` 연산으로 합쳐 `done` 변수 하나에 저장한다. 그리고 DQN 가중치 갱신 단계에서는 `done`이 참이면 다음 상태의 추정 가치를 목표값에서 빼고 즉시 보상만 남긴다.


하지만 규칙상 에피소드가 종료된 상태와 시간 제한으로 중단된 상태는 목표값 계산에서 구분해야 한다. 2026-09-15에 확인한 [Gymnasium 시간 제한 안내](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)는 두 종료 신호의 처리 방식을 나누어 설명한다. 시간 제한으로 중단된 `truncation` 상황에서는 다음 상태의 가치를 이어서 추정하는 **부트스트래핑**(bootstrapping)을 유지한다. 이는 시간 제한 자체가 환경의 상태 정의에 포함된 유한 시간 환경과도 구별되는 개념이다.


![환경 스텝 실행 후 terminated나 truncated 중 하나라도 참이면 에피소드를 종료하지만, 가치 업데이트 목표값에서는 terminated일 때만 즉시 보상을 쓰고 truncated일 때는 다음 상태 가치를 함께 반영하는 순서도](/images/notion/tech-06-04/image-3.png)


그림 3. 에피소드 수집 루프 종료와 목표 가치 계산의 부트스트래핑 중단 조건을 분리한 개념도(출처: Gymnasium 시간 제한 안내를 바탕으로 직접 구성).


결국 데이터 수집 루프를 끝내고 환경을 초기화(`reset`)하는 조건과, 학습 목표값 계산에서 미래 가치를 끊는 조건은 서로 다르다. 현재 코드처럼 두 신호를 하나의 `done`으로 묶어 처리하면, 시간 제한으로 멈춘 스텝에서도 미래 가치가 0인 것처럼 목표값이 계산된다.


## 실행 스크립트와 에이전트 메서드 대조


개별 모듈의 행동 선택과 보상, 종료 신호 처리를 본 뒤, 이를 불러와 실행하는 [학습과 평가 실행](https://github.com/NAMUORI00/ReinforcementLearningLab/blob/aa968aee4cf6776e4f33aff6b776c0863b622816/simple_training.py)(`simple_training.py`) 스크립트를 대조했다. 여기서는 호출하는 쪽과 에이전트 클래스에 정의된 실제 메서드가 맞지 않는 지점이 여럿 보였다.


먼저 평가 함수인 `evaluate_agent`는 에이전트 객체에 `select_action` 메서드가 있는지로 DQN과 DDPG를 구분한다. 그런데 `DQNAgent`와 `DDPGAgent` 모두 `select_action`을 갖고 있어서 DDPG 에이전트를 넘겨도 DQN 분기로 들어간다. 이 분기는 DDPG가 받지 않는 `deterministic` 인자를 넘기므로, 이 경로로는 DDPG 평가가 정상적으로 끝나지 않는다.


학습 루프 쪽에서도 스크립트가 호출하는 이름과 에이전트 클래스의 실제 메서드 정의가 달랐다. DDPG 학습 루프는 `agent.train()`을 호출하지만, 앞서 확인한 `DDPGAgent` 클래스의 가중치 갱신 메서드 이름은 `update`다. 또한 DQN 학습 루프는 에이전트 바깥에서 `update_target_network` 메서드를 따로 호출한다. 하지만 `DQNAgent`는 `update` 메서드 안에서 `hard_update`를 실행할 뿐 같은 이름의 외부 메서드를 두지 않았다.


![simple_training.py에서 호출하는 select_action(deterministic), update_target_network(), agent.train()이 DQNAgent와 DDPGAgent의 실제 메서드 정의와 어긋나는 지점을 비교한 그림](/images/notion/tech-06-04/image-4.png)


그림 4. `simple_training.py`의 호출 경로와 에이전트 클래스 내부에 정의된 실제 메서드 인터페이스의 대조.


이 점들은 해당 커밋의 소스 코드를 대조해 확인한 내용이며, 이번 글을 쓰면서 코드를 고치거나 학습을 다시 돌리지는 않았다. 행동 선택이나 경험 데이터를 모아 두는 리플레이 버퍼, 목표 Q값 계산 같은 개별 개념은 각 모듈 코드 안에서 따라갈 수 있다. 다만 전체 학습과 평가가 끝까지 도는지는 진입점 스크립트의 호출 인자와 메서드 이름까지 맞물려야 확인된다.


## 평가 영상과 결과 기록 조건


실행 스크립트에 이어 [프로젝트 실행 안내](https://github.com/NAMUORI00/ReinforcementLearningLab/blob/aa968aee4cf6776e4f33aff6b776c0863b622816/README.md)(`README.md`)에 적힌 평가 영상 생성 방식을 확인했다. `README.md`에는 실제 학습 결과 파일로 영상을 만드는 방법과 미리 준비된 `sample-data`로 영상을 만드는 방법이 함께 안내되어 있다. 샘플 데이터로 만든 영상은 정책과 실행 흐름을 설명하는 데 쓸 수 있지만, 영상 프레임이 만들어졌다는 사실 자체가 학습 성공의 근거는 아니다. 또한 결과 파일만 보고도 어떤 조건에서 얻은 점수인지 되짚으려면 실행 당시의 설정이 결과와 함께 기록되어야 한다. 탐험 설정과 환경 버전, 보상 변환, 난수 초기값인 시드(seed), 가중치 파일인 체크포인트가 결과와 연결되어야 실행 조건을 되짚을 수 있다.


## 결론


지금까지 확인한 코드와 실행 안내를 종합하면, 강화학습의 학습 점수와 평가 점수는 탐험 여부와 환경 설정에 따라 서로 다른 의미를 갖는다. 학습 곡선은 탐험이 섞인 학습 과정을, 고정된 정책의 평가 분포는 특정 평가 조건의 성능을, 샘플 영상은 동작 설명 자료를 각각 보여 준다. 따라서 평가 결과를 읽을 때는 에이전트 이름에 더해 환경 종류와 보상 스케일, 종료 신호 처리 조건을 함께 보아야 한다.


이번 글에서는 저장소 코드를 대조해 모듈별 행동 선택과 환경 래퍼, 종료 신호 처리 구조를 확인했다. 반면 스크립트의 호출 불일치를 고쳐 학습을 다시 돌리지는 않았으므로, 알고리즘별 평가 호출과 결과 기록 방식은 남은 확인 항목이다. 이어지는 글에서는 여러 에이전트의 판단이 일치하는 정도와 실제 정답 여부를 다룬다.
