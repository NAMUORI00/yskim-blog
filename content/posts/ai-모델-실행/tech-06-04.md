강화학습 실습에서는 DQN과 DDPG의 학습, 평가 흐름을 정리했다. 탐험을 위한 무작위 행동과 잡음, 보상 스케일, 에피소드 종료 신호가 평가 결과에 영향을 주어 각 조건을 구분했다.


## 구현과 확인 과정


ReinforcementLearningLab 저장소의 DQN과 DDPG 코드를 읽으며, 학습과 평가 경로에서 행동 선택이 어떻게 달라지는지 정리했다. 학습 중에는 탐험을 위한 무작위 선택이나 잡음이 섞이므로, 학습 보상이 높아졌더라도 평가에서 같은 행동이 나온다고 보장되지 않는다.


README는 DQN의 Q값 선택과 DDPG의 액터 출력을 비교하는 교육 목적을 설명하고 있었다. 상태, 행동, 보상, 정책은 기초편에서 먼저 다뤘고, 이 글에서는 학습, 평가 실행과 두 에이전트, 환경 래퍼의 연결을 살펴봤다. 해당 커밋의 코드에서 학습, 평가 측정 경로를 확인했다.


## 학습 단계의 탐험 설정


[DQNAgent.select_action](https://github.com/NAMUORI00/ReinforcementLearningLab/blob/aa968aee4cf6776e4f33aff6b776c0863b622816/src/agents/dqn_agent.py)은 epsilon 확률로 무작위 행동을 선택하는 구조였다.


나머지 경우에는 Q값이 가장 큰 행동을 고른다. deterministic=True로 호출하면 무작위 분기를 건너뛴다. Q값은 각 행동 뒤에 기대하는 누적 보상의 추정값이며, 한 스텝에서 즉시 받는 보상과는 다르다.


[DDPGAgent.select_action](https://github.com/NAMUORI00/ReinforcementLearningLab/blob/aa968aee4cf6776e4f33aff6b776c0863b622816/src/agents/ddpg_agent.py)은 액터 네트워크가 연속 행동을 출력하는 구조다.


add_noise=True이면 탐험 노이즈를 더한 뒤 행동 범위를 클리핑한다. 평가에서는 add_noise=False로 노이즈를 끄도록 인터페이스가 분리되어 있었다.


학습 중 에피소드 보상은 탐험과 계속 바뀌는 정책이 함께 만든 결과다. 평가 보상을 별도로 두는 이유는 가중치를 고정하고 탐험 조건을 분리해 현재 정책의 성능만 읽기 위해서다. 탐험을 끄더라도 환경의 초기 상태와 난수까지 고정되지는 않으므로, 여러 평가 에피소드의 보상 분포를 함께 기록해야 단일 에피소드 결과만으로 판단하는 상황을 피할 수 있다.

## 환경 래퍼의 보상 처리


[create_ddpg_env](https://github.com/NAMUORI00/ReinforcementLearningLab/blob/aa968aee4cf6776e4f33aff6b776c0863b622816/src/environments/wrappers.py)는 연속 행동을 −1부터 1 범위로 표현한 뒤 실제 환경의 범위로 변환하는 ActionWrapper를 붙이고 있었다.


보상에는 0.1을 곱하는 RewardScaleWrapper가 적용되어 있었다. 기본 DQN 환경 생성 쪽에는 같은 보상 변환이 없었다.


예를 들어 원래 한 에피소드 보상 합이 −800이면 이 래퍼를 거친 합은 −80이 된다. 이 변화는 보상 스케일 조정의 결과다. 원래 보상과 학습용 보상은 별개의 척도다. 서로 다른 환경의 점수를 비교하려면 스케일과 평가 조건을 함께 맞춰야 한다. 기본 환경 이름부터 DQN은 CartPole, DDPG는 Pendulum으로 다르다.


학습률이나 손실의 수치 범위에 맞추기 위해 보상 스케일을 조정할 수는 있지만, 평가에 같은 변환을 쓰는지, 결과에 어떤 단위를 표시하는지는 별도로 정해야 한다. 이 저장소의 그래프를 설명할 때 래퍼 설정이 결과 파일에 함께 기록되어 있지 않으면 보상 수치의 의미를 나중에 되짚기 어렵다.


## 종료와 시간 제한의 구분


학습, 평가 실행 코드는 환경이 반환한 terminated와 truncated를 OR로 합쳐 done에 저장하고 있었다. DQN 업데이트는 done이 참이면 다음 상태의 추정 가치를 목표값에서 빼서 즉시 보상만 남긴다. 환경의 종결과 외부 시간 제한은 다음 상태 가치의 반영 여부를 판단할 때 구분해야 한다.


2026-09-15에 확인한 [Gymnasium 시간 제한 안내](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)는, 외부 중단인 truncation에서는 다음 상태의 가치를 이어 추정하는 부트스트래핑을 유지하도록 설명하고 있었다.


환경 정의 자체에 포함된 유한 시간 종료와도 구분되어 있었다. 실행 루프를 끝내는 조건과 학습 목표에서 미래 가치를 끊는 조건은 별개이며, 현재 코드는 이 둘을 하나의 done으로 처리하고 있다.

## 평가 함수의 호출 경로


[학습과 평가 실행](https://github.com/NAMUORI00/ReinforcementLearningLab/blob/aa968aee4cf6776e4f33aff6b776c0863b622816/simple_training.py)의 evaluate_agent는 select_action 메서드가 있는지로 DQN과 DDPG를 구분하고 있었다.


두 클래스 모두 select_action을 갖고 있으므로, DDPG 에이전트를 그대로 전달하면 DQN 분기로 들어간다. 이 경우 DDPG가 받지 않는 deterministic 인자가 넘어가는 문제가 생긴다. 이 경로로는 정상적인 DDPG 평가가 완료되지 않는다.


학습 호출 쪽에도 인터페이스가 맞지 않는 부분이 있었다. DDPG 루프는 agent.train()을 호출하지만, 확인한 DDPGAgent의 갱신 메서드 이름은 update다.


DQN 루프는 update_target_network를 별도로 호출하지만, 클래스는 update 내부에서 hard_update를 수행하며 같은 이름의 외부 메서드를 제공하지 않는다. 이들은 소스 코드 사이의 인터페이스 차이를 확인한 결과이며, 이번 글을 위해 코드를 수정하거나 학습을 다시 실행하지는 않았다.


개념 설명 모듈과 실행 가능한 진입점은 분리해서 읽을 수 있었다. 행동 선택, 리플레이 버퍼, 목표 Q값 계산은 각 모듈 안에서 따라갈 수 있고, 전체 학습, 평가가 끝까지 도는지는 이들을 호출하는 스크립트의 인터페이스까지 맞춰 실행해 봐야 확인된다.


## 평가 영상과 입력 자료의 연결


README에는 실제 결과 파일을 사용한 영상과 sample-data로 만든 영상이 모두 안내되어 있었다. 샘플 영상은 정책과 학습 흐름을 설명하는 데 쓸 수 있지만, 프레임이 생성됐다는 사실 자체가 에이전트 학습 성공의 증거가 되지는 않는다.


[프로젝트 실행 안내](https://github.com/NAMUORI00/ReinforcementLearningLab/blob/aa968aee4cf6776e4f33aff6b776c0863b622816/README.md)


이 저장소를 읽고 남은 확인 항목은 알고리즘별 평가 호출과 결과 기록 방식이었다. 탐험 설정, 환경 버전, 보상 변환, seed, 체크포인트가 결과와 연결되어야 실행 조건을 되짚을 수 있다. 학습 곡선은 학습 과정, 고정 정책의 평가 분포는 평가 조건에서의 성능, 샘플 영상은 설명 자료로 읽었다. 이어지는 글에서는 여러 에이전트의 판단이 일치하는 정도와 실제 정답 여부를 살펴본다.


## 작업을 정리하며


평가를 읽을 때는 에이전트 이름에 더해 환경, 보상, 종료 조건을 함께 보아야 한다. 특히 시간 제한과 환경 종결을 나누면 부트스트래핑이 멈추는 이유가 드러난다. 코드의 작은 조건이 학습 목표를 바꾼다는 점을 기억해 두고 싶다.
