음성 처리 작업에서는 gptToVoice와 OSC-SRTC의 마이크 입력을 문자와 제어 메시지로 이어 붙이는 흐름을 다뤘다. 녹음, 인식, 번역, 응답 생성, 전송의 상태가 서로 달라 각 단계의 결과가 다음 단계에 전달되는 방식을 정리했다.


## 구현과 확인 과정


gptToVoice와 OSC-SRTC의 코드를 읽으며 마이크 입력이 처리되는 경로를 따라가 봤다. gptToVoice는 녹음한 오디오를 문자로 인식해 화면에 표시하고, OSC-SRTC는 인식, 번역한 문장을 VRChat 채팅으로 보낸다. 두 경로는 인식한 음성을 문자와 제어 메시지로 전달한다.


음성 인식은 소리에서 문자를 얻는 처리이고, 음성 합성은 문자에서 소리를 만드는 처리다. 이번 글에서는 NAMUORI00/gptToVoice의 eda4f8b와 NAMUORI00/OSC-SRTC의 627b1a4 커밋에서, 오디오, 문자, 제어 메시지가 바뀌는 경계를 따라갔다.


OSC-SRTC의 README가 안내하는 원본 프로젝트는 rera-vrc/OSC-SRTC이며, 그 기능을 개인의 신규 구현으로 계산하지 않았다.


## 녹음 파일을 먼저 완성하는 gptToVoice


[마이크 녹음 처리](https://github.com/NAMUORI00/gptToVoice/blob/eda4f8b6a3c3b039532077e793c7baf67e6bec4b/record.py)는 sounddevice 입력 콜백에서 받은 배열을 큐에 넣고, 별도 스레드가 이를 녹음 파일에 쓴다.


파일 조건은 16 kHz, 단일 채널, PCM 16비트다. 콜백에서 파일 저장을 직접 끝내기보다 녹음 데이터 전달과 쓰기를 나누어 둔 구성이 보였다.


[녹음 종료와 인식 연결](https://github.com/NAMUORI00/gptToVoice/blob/eda4f8b6a3c3b039532077e793c7baf67e6bec4b/module_mic.py)의 end는 녹음을 멈춘 다음 파일을 음성 인식 함수에 넘긴다.


[음성 인식 처리](https://github.com/NAMUORI00/gptToVoice/blob/eda4f8b6a3c3b039532077e793c7baf67e6bec4b/Scrap_code/translate.py)는 Google Cloud Speech의 recognize를 호출하고 각 결과의 첫 번째 후보 문장을 합친다. 녹음 중간 결과를 지속적으로 표시하는 스트리밍 인식과는 다른, 파일 단위 처리다.


![09-04-01.png](/images/notion/tech-09-04/image-1.png)


그림 1. gptToVoice에서 녹음 파일이 인식 문장과 텍스트 응답으로 바뀌는 경로. 출처: 마이크 녹음 처리, 녹음 종료, 인식 연결, 음성 인식 처리, 녹음, 문장 입력 화면, 언어 모델 요청 처리를 바탕으로 직접 구성. 확인한 경로에는 응답을 읽어 주는 음성 합성 단계가 없다.


[녹음과 문장 입력 화면](https://github.com/NAMUORI00/gptToVoice/blob/eda4f8b6a3c3b039532077e793c7baf67e6bec4b/app.py)은 Record, Stop, Input 상태로 버튼을 바꾸고, 인식된 문장을 입력란에 넣는다.


사용자는 문장을 확인한 뒤 텍스트 생성 요청을 보낼 수 있다. 이후 응답을 화면에 표시하고 입력, 프리셋, 시각, 응답을 JSON과 표에 기록한다.


[언어 모델 요청 처리](https://github.com/NAMUORI00/gptToVoice/blob/eda4f8b6a3c3b039532077e793c7baf67e6bec4b/main.py)의 요청은 그 시점의 Completion 인터페이스와 text-davinci-003 이름을 사용한다. 저장된 코드의 연결 관계를 읽은 기록이며, 현재도 같은 설정으로 동작하는지는 확인하지 않았다.


표에 저장된 대화 기록과 다음 요청에 포함되는 문맥은 별도로 구성됐다. 호출 인자는 현재 프리셋과 입력 문장이다. 기록 보관과 이전 대화의 모델 문맥 전달은 별개의 기능으로 분리되어 있었다.


## OSC-SRTC의 채팅 메시지 전송


[음성 인식, 번역, 채팅 연결](https://github.com/NAMUORI00/OSC-SRTC/blob/627b1a431dfc11b7ea5f9a1a43a28096b7570134/OSC-SRTC.py)의 반복문은 음성을 인식한 다음, 원문 언어와 목표 언어가 다르면 번역한다.


두 번째 목표 언어가 설정되어 있으면 그 번역을 괄호 안에 덧붙인다. 이후 확장 처리기를 거쳐 /chatbox/input으로 문장과 True를 보낸다.


OSC 메시지는 인식, 번역된 문자와 제어 정보를 전달한다. [OSC 메시지 전송](https://github.com/NAMUORI00/OSC-SRTC/blob/627b1a431dfc11b7ea5f9a1a43a28096b7570134/modules/SRTC_OSC.py)은 주소와 인자를 UDP 클라이언트로 보낸다.


[VRChat 공식 문서](https://docs.vrchat.com/docs/osc-as-input-controller)에 따르면 /chatbox/input의 불리언 값이 True일 때 문장이 즉시 전송된다. 같은 OSC라도 채팅 문자열과 아바타 상태 값은 주소와 인자 형식이 다르다.


![09-04-02.png](/images/notion/tech-09-04/image-2.png)


그림 2. OSC-SRTC에서 인식, 번역한 문장이 채팅 전송으로 이어지는 조건 분기. 출처: 음성 인식, 번역, 채팅 연결과 문장 확장 처리를 바탕으로 직접 구성. 두 번째 언어 결합과 로마자 표기는 본문에서 설명하고 도식에서는 생략했다.


## 확장 준비와 메시지 수신 상태


[문장 확장 처리](https://github.com/NAMUORI00/OSC-SRTC/blob/627b1a431dfc11b7ea5f9a1a43a28096b7570134/modules/SRTC_Extension.py)는 등록된 확장 서버에 HTTP로 문장을 전달한다.


응답이 정상이라면 반환된 문장을 다음 확장으로 넘기고, 특별한 문자열 {Sended-Already}를 만나면 이후 처리를 멈춘다. 메인 반복문도 이 값을 보고 기본 OSC 전송을 생략한다.


이 문자열은 확장과 메인 프로그램 사이의 약속이다. 수신 화면에 문장이 나타났다는 확인 응답으로 읽지는 않았다. 기본 OSC 래퍼에서도 보낸 메시지에 대한 응용 수준의 수신 확인이나 재전송 상태를 관리하는 코드는 보이지 않았다.


확장 실행의 HTTP 요청에는 명시적인 timeout 인자가 없었고, 확장 목록 잠금을 잡은 상태에서 응답을 기다린다. 외부 처리가 지연되면 메시지 전달뿐 아니라 목록을 수정하는 경로까지 대기하는 구조다. 확장별 처리 지연은 별도 실행 측정 항목으로 남아 있다.


## 진행 상태 표시의 확인 항목


gptToVoice의 진행 막대는 녹음, 인식, 요청 단계에서 30, 60, 80, 100으로 설정된다. 이 값은 처리 상태를 화면에 표시하기 위한 수치다. 인식과 텍스트 생성도 버튼 콜백에서 동기적으로 호출되므로, 오래 걸리는 요청이 있을 경우 그 동안 화면이 멈추는지 여부는 별도 확인 항목으로 남아 있다.


두 프로젝트를 함께 읽으면서 처리 결과를 하나의 성공 여부로 묶기보다 녹음 저장, 문자 인식, 번역 또는 응답 생성, 전송, 화면 확인으로 나누어 보는 편이 각 단계의 상태를 구분하기 쉬웠다.


예를 들어 인식된 “안녕하세요”가 “Hello”로 번역되었다면, 번역 문자열 생성과 VRChat 화면 표시는 서로 다른 확인 지점이다. 이번에는 마이크 녹음, 외부 API 요청, 실제 채팅 전송을 실행하지 않았으며 이 예는 상태를 설명하기 위한 것이다.


다음 글에서는 같은 오디오 입력이 문자 대신 MIDI와 악보로 바뀌는 doremi-sketch를 살펴본다. 중간 결과의 자료형이 달라졌을 때 사용되는 도구와 결과의 신뢰 범위도 함께 정리할 예정이다.


## 작업을 정리하며


음성 기능을 서비스에 붙일 때는 결과 문자열이 만들어진 시점과 화면에 표시된 시점을 나누는 편이 좋다. 단계별 상태와 지연을 남기면 외부 API 대기와 전송 문제를 구분할 수 있다. 이후에는 진행 표시도 실제 처리 단계에 맞춰 구성하려 한다.
