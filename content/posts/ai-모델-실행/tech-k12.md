## 프레임별 검출 결과


영상의 검출과 추적을 정리하며 프레임별 박스와 대상 ID를 나누어 읽었다. 여기서는 프레임 하나씩 처리하는 이미지 검출기를 가정한다. 연속된 박스가 같은 사람을 가리키는지 판단하려면 프레임 사이의 연결과 시간 정보가 더 필요하다.


프레임, 타임스탬프, 검출, 추적의 역할을 작은 예제로 따라갔다. 위치를 찾은 결과와 같은 대상을 계속 연결한 결과가 각 단계에서 어떻게 표현되는지 정리했다.


## 프레임과 타임스탬프


영상 파일을 열면 프레임 인덱스와 타임스탬프를 함께 읽을 수 있다. 30fps 영상이면 프레임 0은 0.000초, 프레임 1은 약 0.033초, 프레임 2는 약 0.067초에 대응한다. 일정한 30fps, 0부터 시작하는 인덱스, 시작 시각 0이라는 가정에서는 인덱스를 fps로 나누어 상대 시각을 계산할 수 있었다. 프레임 90이면 90 ÷ 30 = 3.000초다.


이 대응이 항상 균등하지는 않다. 가변 프레임률(VFR) 영상이나 드랍 프레임이 섞이면 인덱스 간격과 시간 간격이 달라진다. 프레임 인덱스는 순서를, 프레임 타임스탬프는 해당 미디어의 시간축 위치를 나타낸다.


촬영 장소의 실제 시계와 맞추려면 별도 기준 시각과 동기화 정보가 필요하다. 둘을 구분해두면 "인덱스 5"를 "약 0.167초 시점"이라고 말할 수 있어서, 서로 다른 fps의 영상을 비교하거나 이벤트 시각을 외부 로그와 맞출 때 혼동이 줄어든다.


## 검출: 프레임 하나의 스냅숏


객체 검출은 프레임 하나를 입력으로 받아 바운딩 박스 목록을 출력한다. 세 프레임에 걸쳐 두 사람이 움직이는 상황을 예로 들어 보자.


| 프레임 | 시각(초) | 검출 결과                                          |
| --- | ----- | ---------------------------------------------- |
| 0   | 0.000 | A: [100, 50, 150, 200], B: [300, 60, 350, 210] |
| 1   | 0.033 | C: [105, 52, 155, 202], D: [298, 58, 348, 208] |
| 2   | 0.067 | E: [110, 55, 160, 205], F: [295, 55, 345, 205] |


A~F는 여기서 구분을 위해 붙인 이름이다. 검출기는 프레임 사이의 대응을 계산하지 않았으므로 A와 C가 같은 사람인지 알 수 없다. 프레임 간 동일 인물 여부는 좌표를 비교하는 별도의 추적 단계에서 판단한다.


## 추적: 프레임 사이에서 같은 객체 잇기


추적(tracking)은 프레임 간 검출 결과를 연결해서 객체마다 고유 ID를 유지하는 작업이다. SORT(Simple Online and Realtime Tracking, [Bewley et al., 2016](https://arxiv.org/abs/1602.00763))의 접근을 빌려 설명하면 두 단계로 나뉜다.


**예측**: 이전 프레임의 박스 위치와 속도로 현재 프레임에서의 예상 위치를 계산한다. 칼만 필터가 이 역할을 맡는다. 원 SORT는 박스 중심, 면적, 가로세로 비와 중심, 면적의 변화율을 상태로 표현한다. 가로세로 비의 변화율까지 포함하는 일반적인 위치, 크기 모델과 혼동하지 않았다.


**매칭**: 예측 위치와 실제 검출 박스 사이의 IoU(Intersection over Union)를 계산하고, 헝가리안 알고리즘으로 총 비용이 최소인 대응 쌍을 선택한다. IoU는 두 박스의 교집합 면적을 합집합 면적으로 나눈 값이다.


두 박스가 정확히 겹치면 1.0, 전혀 겹치지 않으면 0.0이 된다. 예를 들어 50×50 박스 두 개가 25×50만큼 겹치면 교집합은 1,250, 합집합은 5,000 - 1,250 = 3,750이므로 IoU는 1,250 ÷ 3,750 ≈ 0.33이다.


앞의 예제에 적용하면 프레임 0에서 A와 B가 각각 ID 1, ID 2로 초기화된다. 프레임 1에서 칼만 필터가 ID 1의 예상 위치를 내놓고, 전체 할당 결과와 매칭 임계값을 만족하면 C를 같은 ID로 연결할 수 있다.


각 객체가 독립적으로 최고 IoU만 고르는 탐욕적 매칭과는 구분해야 했다. B와 D도 마찬가지로 ID 2가 된다. 프레임 2에서도 같은 과정이 반복되어, 세 프레임에 걸친 이동 경로가 완성된다.

## 추적이 끊기는 경우


객체가 다른 물체에 가려지거나 프레임 밖으로 나가면 검출 결과가 사라진다. 예측은 있지만 매칭할 검출이 없으므로 추적기는 일정 프레임 동안 예측 위치만 유지하다가, 설정한 한계를 넘기면 해당 ID를 삭제한다. 반대로 기존 ID와 매칭되지 않는 새 검출이 나타나면 새 ID가 부여된다. ID가 한번 삭제된 뒤 같은 사람이 다시 나타나면 다른 번호를 받게 된다.

SORT 원논문은 검출기를 바꾸었을 때 해당 실험의 추적 지표가 달라졌다고 보고했다. 이 결과는 임의의 영상이나 프로젝트에서 측정한 성능과는 구분된다. 추적 방식을 비교할 때 프레임별 검출 품질도 함께 점검할 근거로 읽었다.


OpenCV의 [Tracking API](https://docs.opencv.org/4.10.0/dc/d6b/group__video__track.html)는 여러 추적 기능을 제공하며 알고리즘과 버전에 따라 모듈 위치가 다르다. 단일 객체 추적과 다중 객체 ID 할당을 구분한 뒤 작은 영상에서 필요한 기능을 확인하는 작업이 남았다.


## 후속 검토


빠른 움직임이나 긴 가림은 IoU 기반 매칭이 어려워질 수 있는 조건이다. 외형 특징(appearance feature)을 함께 사용하는 방식은 이 조건을 비교할 후속 주제로 정리했다.


[Deep SORT(Wojke et al., 2017)](https://arxiv.org/abs/1703.07402)는 외형 특징을 사용하는 확장이다. 가변 프레임률에서 칼만 필터의 시간 간격 가정을 조정하는 문제도 함께 살펴볼 내용으로 남겼다.
