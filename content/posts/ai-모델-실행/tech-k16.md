## GPU 메모리와 학습 시간 제약


여러 GPU로 학습할 때 나누는 대상을 정리했다. 모델이 메모리에 들어가지 않는 경우와 들어가지만 학습이 오래 걸리는 경우는 선택 조건이 다르다. 가중치, 활성값, 기울기, 옵티마이저 상태의 저장량을 염두에 두고 데이터, 연산, 레이어 분할을 비교했다.


## 데이터 병렬의 배치 분할과 기울기 집계


데이터 병렬(Data Parallelism)은 가장 직관적인 접근이다. 모델 전체를 각 GPU에 복제해 두고, 입력 배치를 GPU 수만큼 쪼개어 각각 독립적으로 순전파와 역전파를 수행한다. 그 뒤 모든 GPU의 기울기를 평균 내어(all-reduce) 동일한 가중치 갱신을 적용한다.


GPU 2개에 배치 크기 32를 나누는 경우를 보자. GPU 0은 16개, GPU 1은 16개 샘플로 각각 기울기를 구한다. 각 샘플 손실을 같은 비중으로 평균 내고 모델 상태가 같다면, 두 기울기의 평균은 전체 32개 샘플 손실의 기울기에 대응한다. 배치에 의존하는 연산, 난수, 부동소수점 합산 순서에 따라 학습 결과에 차이가 생길 수 있다.


제약도 명확하다. 모델 전체를 각 GPU에 올려야 하므로, 모델이 GPU 메모리보다 크면 이 방식만으로는 학습을 시작할 수 없다.


PyTorch의 `DistributedDataParallel`이 이 방식의 표준 구현에 해당한다([docs.pytorch.org — DistributedDataParallel](https://docs.pytorch.org/docs/stable/generated/torch.nn.parallel.DistributedDataParallel.html)).


## 텐서 병렬의 연산 분할


텐서 병렬(Tensor Parallelism)은 단일 레이어 안의 행렬 연산을 여러 GPU에 분배한다. 크기 4096×4096인 가중치 행렬 W를 열 방향으로 반씩 쪼개면, GPU 0은 4096×2048 조각, GPU 1도 4096×2048 조각을 갖게 된다.


입력 벡터 x에 대해 y = xW를 계산할 때, 각 GPU는 자기 조각과 곱한 부분 결과를 내놓고 이를 이어붙이면 전체 결과가 된다. 이어지는 연산의 행, 열 분할을 맞추면 매 단계 전체 텐서를 모으는 일을 줄일 수 있다. Transformer 블록 전체에서는 다른 연산 단계에도 통신이 발생한다.


어텐션과 MLP, 순전파와 역전파별 통신을 나눠 확인해야 했다. Megatron-LM에서 이런 분할 조합을 참고했다([arxiv.org/abs/2104.04473](https://arxiv.org/abs/2104.04473)).


텐서 병렬은 분할한 연산 사이에서 통신이 자주 필요하므로, 같은 노드 안에서 NVLink처럼 대역폭이 높은 연결을 갖춘 환경에서 효과적이다. 노드 간 네트워크를 통한 통신에서는 지연이 크게 늘어날 수 있다.


## 파이프라인 병렬의 레이어 배치


파이프라인 병렬(Pipeline Parallelism)은 모델의 레이어를 연속 블록(스테이지)으로 나누어 각 GPU에 배치한다. 12-레이어 모델을 GPU 3개로 나누면, GPU 0이 레이어 1~4, GPU 1이 5~8, GPU 2가 9~12를 맡는 식이다.


단순하게 구현하면 한 GPU가 계산하는 동안 나머지가 대기하게 된다. 이 유휴 시간(bubble)을 줄이기 위해 배치를 작은 마이크로배치로 나누어, 앞선 마이크로배치가 다음 스테이지로 넘어가는 즉시 뒤따르는 마이크로배치를 처리하는 방식으로 파이프라인을 구성한다.


GPipe가 이 접근의 대표적 구현이다([arxiv.org/abs/1811.06965](https://arxiv.org/abs/1811.06965)).

## 병렬화 방식별 통신과 메모리 부담


세 방식이 무엇을 나누고 언제 통신하는지를 정리하면 차이가 선명해진다.


| 방식       | 나누는 대상   | 통신 시점              | 메모리 이점                     |
| -------- | -------- | ------------------ | -------------------------- |
| 데이터 병렬   | 입력 배치    | 역전파와 겹쳐 기울기 동기화 가능 | 파라미터 복제, 로컬 배치의 활성값은 감소 가능 |
| 텐서 병렬    | 레이어 내 행렬 | 순전파와 역전파 중         | 파라미터 분산                    |
| 파이프라인 병렬 | 레이어 블록   | 스테이지 경계            | 파라미터 분산                    |


일반적인 데이터 병렬은 모델을 복제하므로 모델 자체의 저장량을 줄이지 못한다. 텐서 병렬은 레이어 내부를 나누는 대신 빈번한 통신이 따른다. 파이프라인 병렬은 경계의 활성값과 기울기를 전달하며, 그 텐서 크기와 스테이지 불균형, 시작 및 종료 대기가 비교 조건이 된다.

## 병렬화 방식의 조합


실제 대규모 학습에서는 세 방식을 함께 사용하는 경우가 많다. 같은 노드 안 GPU끼리는 텐서 병렬로 하나의 레이어를 분할하고, 노드 사이에는 파이프라인 병렬로 레이어 블록을 배분하며, 그 위에 데이터 병렬을 겹쳐 수천 GPU까지 확장하는 구조가 일반적인 패턴이다. Megatron-LM 논문에서 이 3차원 조합의 설계 지침을 확인할 수 있다.


## 병렬화 설정의 확인 항목


모델과 학습 상태가 장치 하나에 들어가는지를 선택의 출발점으로 정리했다. 들어가는 경우 데이터 병렬을 기준선으로 볼 수 있고, 부족하면 텐서, 파이프라인 병렬과 FSDP, ZeRO의 상태 분할도 비교 대상이 된다.


데이터 병렬에서 GPU 수를 늘리면 GPU당 배치 크기가 줄어든다. 전역 배치 크기와 평균 손실을 유지할 때 최종 평균 기울기의 표본 분산은 전역 표본 구성을 기준으로 해석한다.


로컬 작업량이 줄면 GPU 활용률이 낮아지고 통신 비중이 커져 장치 수에 비례한 가속이 어려울 수 있다. 전역 배치를 유지한 상태에서 데이터 병렬의 복제 비용과 모델 병렬의 통신 비용을 비교하는 작업을 후속 주제로 남겼다.
