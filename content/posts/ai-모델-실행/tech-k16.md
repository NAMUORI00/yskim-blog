딥러닝 모델을 학습할 때 GPU 메모리에는 모델의 가중치(weight)만 올라가지 않는다. 순전파에서 계산한 활성값(activation), 역전파에서 구한 기울기(gradient), 가중치를 갱신하는 옵티마이저 상태(optimizer state)까지 모두 메모리를 차지한다. 그래서 여러 GPU로 분산 학습을 구성할 때는 현재 겪고 있는 제약이 무엇인지부터 구분해야 한다. 모델과 학습 상태가 GPU 하나에 충분히 들어가지만 많은 데이터를 빨리 학습하고 싶은 경우와, 모델 자체가 너무 커서 GPU 하나의 메모리에 들어가지 않는 경우는 나누어야 할 대상이 다르다. 입력 데이터를 나누는 데이터 병렬, 레이어 내부 연산을 나누는 텐서 병렬, 레이어 구간을 나누는 파이프라인 병렬이 각각 무엇을 분할하고 언제 통신하는지 비교해 본다.

그림 1. 세 가지 병렬화 방식의 분할 대상 비교 개념도. 데이터 병렬은 입력 배치를, 텐서 병렬은 레이어 안의 행렬 연산을, 파이프라인 병렬은 레이어 구간을 나눈다.


## 데이터 병렬: 입력 배치를 나누고 기울기를 모은다


**데이터 병렬**(Data Parallelism)은 모델 전체를 모든 GPU에 똑같이 복제해 두고, 입력 데이터 배치만 GPU 수만큼 쪼개어 처리하는 방식이다. 각 GPU는 자기가 맡은 데이터 조각으로 순전파와 역전파를 독립적으로 수행해 기울기를 구한다. 그 뒤 모든 GPU의 기울기를 모아 평균을 내고(all-reduce), 모든 GPU의 모델에 똑같은 가중치 갱신을 적용한다.


크기가 32인 배치를 GPU 2개에 나누어 학습하는 경우를 생각해 보자. GPU 0과 GPU 1은 각각 샘플 16개씩을 받아 기울기를 계산한다. 각 샘플의 손실을 같은 비중으로 평균 내어 전체 손실을 구하고 두 GPU의 모델 상태가 같다면, 두 GPU가 각자 구한 기울기의 평균은 샘플 32개 전체 손실의 기울기와 수식상 일치한다. 다만 배치 정규화(Batch Normalization)처럼 배치 안에 들어 있는 샘플들의 통계에 의존하는 연산이 있거나, 난수 상태와 부동소수점 덧셈 순서가 달라지면 단일 GPU로 학습할 때와 결과에 차이가 생길 수 있다.


데이터 병렬은 구조가 직관적이지만 제약도 분명하다. 각 GPU가 모델 전체를 온전히 올려야 하므로, 모델이 단일 GPU 메모리보다 크면 이 방식만으로는 학습을 시작할 수 없다. PyTorch에서는 `DistributedDataParallel`이 이 방식의 표준 구현에 해당한다([docs.pytorch.org — DistributedDataParallel](https://docs.pytorch.org/docs/stable/generated/torch.nn.parallel.DistributedDataParallel.html)).


## 텐서 병렬: 레이어 안의 행렬 연산을 나눈다


모델이 GPU 하나에 들어가지 않을 때는 모델 자체를 여러 GPU에 나누어 올려야 한다. 그중 **텐서 병렬**(Tensor Parallelism)은 단일 레이어 안에 있는 행렬 연산을 여러 GPU에 분배하는 방식이다. 예를 들어 크기가 4096×4096인 가중치 행렬 $W$를 열(column) 방향으로 반씩 쪼개면, GPU 0과 GPU 1은 각각 4096×2048 크기의 가중치 조각을 갖는다.


![가중치 행렬 W를 두 GPU에 열 방향으로 나누어 곱하고 결과를 합치는 텐서 병렬 다이어그램](/images/notion/tech-k16/image-2.png)


그림 2. 텐서 병렬에서 가중치 행렬 W를 열 방향으로 나누어 계산하는 과정(개념도). 각 GPU가 4096×2048 조각과의 곱셈을 수행한 뒤 부분 결과를 이어붙여 전체 출력 y를 만든다.


입력 벡터 $x$에 대해 행렬 곱 $y = xW$를 계산할 때, 각 GPU는 같은 입력 $x$에 자기 가중치 조각을 곱한 부분 결과를 내놓고, 이를 열 방향으로 이어붙이면 전체 출력 $y$가 된다. 이때 바로 이어지는 다음 연산의 행과 열 분할 방향을 맞추어 두면 매 단계마다 전체 텐서를 모으는 통신을 줄일 수 있다.


트랜스포머(Transformer) 블록 전체에 텐서 병렬을 적용할 때는 다른 연산 단계에서도 통신이 발생하므로 어텐션(Attention)과 다층 퍼셉트론(MLP), 순전파와 역전파별 통신 시점을 나누어 맞추어야 한다. Megatron-LM 논문에서 이러한 행렬 분할 조합을 확인할 수 있다([arxiv.org/abs/2104.04473](https://arxiv.org/abs/2104.04473)).


텐서 병렬은 분할한 연산 사이에서 통신이 자주 필요하므로, 같은 서버(노드) 안에서 NVLink처럼 대역폭이 높은 연결을 갖춘 환경에서 효과적이다. 노드 간 네트워크를 거쳐 통신하면 지연 시간이 크게 늘어날 수 있다.


## 파이프라인 병렬: 레이어를 구간별로 묶어 배치한다


**파이프라인 병렬**(Pipeline Parallelism)은 레이어 내부의 행렬을 쪼개는 대신, 모델의 레이어를 연속된 블록(스테이지, stage)으로 나누어 각 GPU에 배치한다. 예를 들어 12개 레이어로 이루어진 모델을 GPU 3개로 나누면 GPU 0이 레이어 1~4, GPU 1이 레이어 5~8, GPU 2가 레이어 9~12를 맡는다.


배치 하나를 통째로 넣는 단순한 구조에서는 한 GPU가 계산하는 동안 나머지 GPU가 앞 단계의 결과를 기다리며 대기하게 된다. 이 유휴 시간(bubble)을 줄이기 위해 파이프라인 병렬에서는 배치를 더 작은 마이크로배치(micro-batch) 여러 개로 나눈다. 앞선 마이크로배치가 첫 스테이지 계산을 마치고 다음 스테이지로 넘어가는 즉시, 첫 스테이지가 뒤따르는 마이크로배치를 받아 처리하는 방식이다. GPipe가 이 접근의 대표적인 구현이다([arxiv.org/abs/1811.06965](https://arxiv.org/abs/1811.06965)).


![세 개의 GPU 스테이지 사이에서 마이크로배치의 활성값과 경계 기울기가 전달되는 파이프라인 병렬 다이어그램](/images/notion/tech-k16/image-3.png)


그림 3. 파이프라인 병렬에서 마이크로배치가 스테이지를 통과하는 흐름(개념도). 앞선 마이크로배치가 다음 스테이지로 활성값을 넘기면 이전 스테이지는 즉시 다음 마이크로배치를 처리한다.


## 방식별 통신 시점과 메모리 부담 비교


세 가지 병렬화 방식이 무엇을 나누고 언제 통신하는지 비교하면 각각의 특성이 분명하게 드러난다.


| 방식       | 나누는 대상   | 통신 시점              | 메모리 이점                     |
| -------- | -------- | ------------------ | -------------------------- |
| 데이터 병렬   | 입력 배치    | 역전파와 겹쳐 기울기 동기화 가능 | 파라미터 복제, 로컬 배치의 활성값은 감소 가능 |
| 텐서 병렬    | 레이어 내 행렬 | 순전파와 역전파 중         | 파라미터 분산                    |
| 파이프라인 병렬 | 레이어 블록   | 스테이지 경계            | 파라미터 분산                    |


기본적인 데이터 병렬은 모델을 모든 GPU에 복제하므로 모델 가중치 자체의 저장량을 줄이지 못한다. 다만 GPU마다 맡는 로컬 배치 크기가 줄어들어 활성값 메모리는 줄일 수 있다. 텐서 병렬은 레이어 내부를 나누어 가중치를 분산하는 대신 순전파와 역전파 도중에 빈번한 통신이 따른다. 파이프라인 병렬은 스테이지 경계에서만 활성값과 기울기를 전달하므로 통신 빈도는 낮지만, 경계에서 주고받는 텐서의 크기와 스테이지 간 연산량 불균형, 시작 및 종료 구간의 대기 시간이 성능 비교 조건이 된다.


## 대규모 학습에서의 조합과 선택 기준


실제 대규모 학습에서는 한 가지 방식만 쓰기보다 세 방식을 함께 조합하는 경우가 많다. 같은 노드 안의 GPU끼리는 텐서 병렬로 하나의 레이어를 분할하고, 노드 사이에는 파이프라인 병렬로 레이어 블록을 배분하며, 그 위에 데이터 병렬을 겹쳐 수천 개의 GPU까지 확장하는 구조가 널리 쓰인다. Megatron-LM 논문에서 이 3차원 조합의 설계 지침을 다룬다.


![노드 내 텐서 병렬, 노드 간 파이프라인 병렬, 복제본 간 데이터 병렬을 결합한 3차원 병렬화 구조도](/images/notion/tech-k16/image-4.png)


그림 4. 대규모 학습에서 세 가지 병렬화 방식을 결합한 3차원 병렬화 구조(개념도). 같은 노드 안에서는 텐서 병렬을, 노드 사이에는 파이프라인 병렬을 적용하고 전체 파이프라인 묶음을 복제해 데이터 병렬로 확장한다.


병렬화 구성을 고를 때는 모델과 학습 상태가 장치 하나에 들어가는지가 첫 번째 기준이 된다. 장치 하나에 들어간다면 구조가 단순한 데이터 병렬을 기본 기준선으로 삼을 수 있다. 메모리가 부족하다면 텐서 병렬이나 파이프라인 병렬로 모델을 나누거나, 데이터 병렬 구조에서 가중치와 기울기, 옵티마이저 상태를 GPU 사이에 나누어 보관하는 ZeRO와 PyTorch FSDP(Fully Sharded Data Parallel) 같은 상태 분할 방식도 비교 대상이 된다.


한편 데이터 병렬에서 전체 배치 크기(전역 배치 크기)를 유지한 채 GPU 수를 늘리면 GPU당 처리하는 로컬 배치 크기가 줄어든다. 전역 배치 크기와 손실 평균 방식이 같다면 최종 평균 기울기의 표본 분산은 전역 표본 구성을 그대로 따른다. 그러나 각 GPU의 로컬 작업량이 너무 줄어들면 GPU 연산 활용률이 낮아지고 전체 학습 시간에서 통신 비중이 커져, 장치 수에 비례한 속도 향상을 얻기 어려울 수 있다. 전역 배치를 유지한 상태에서 데이터 병렬의 복제 비용과 모델 병렬의 통신 비용을 비교하는 작업은 후속 주제로 남겼다.
