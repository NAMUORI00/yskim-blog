이미지에서 특정 색을 띤 영역만 골라낼 때는 각 점(픽셀)의 색 값이 정해 둔 범위 안에 들어오는지 검사한다. 이 검사로 원하는 부분만 남기고 나머지는 가리는 흑백 판을 **마스크**(mask)라고 부른다. 흔히 쓰는 RGB 색공간은 색을 숫자로 표현할 때 빨강(R), 초록(G), 파랑(B) 세 가지 빛의 밝기(채널)를 조합한다. 예를 들어 빨간 물체를 찾으려고 `R > 150`, `G < 50`, `B < 50` 같은 조건을 걸면, 밝은 조명 아래에 있는 빨간 물체는 잘 걸러진다. 그런데 같은 물체가 그늘로 들어가 어두워지면 R 값이 100 정도로 내려가면서 조건에서 빠진다.


RGB 색공간에서는 이처럼 색의 종류와 밝기가 세 채널 값에 함께 섞여 있다. 조명이 어두워지면 세 채널 값이 모두 줄어들기 때문에, 밝은 환경에 맞춰 고정해 둔 RGB 범위로는 그늘진 곳의 같은 색을 잡기 어렵다. 이 글에서는 색의 종류와 밝기를 분리해 표현하는 HSV 색공간의 원리를 픽셀 계산으로 확인하고, OpenCV로 색상 마스크를 만드는 과정과 한계를 다룬다.


## HSV 색공간과 밝기 변화


그늘진 곳에서도 같은 색을 찾아내려면 색의 종류와 밝기를 따로 다루는 HSV 색공간을 쓴다. HSV는 **색상**(Hue, H), **채도**(Saturation, S), **명도**(Value, V) 세 축으로 색을 나눈다. 여기서 H 축은 빨강이나 파랑 같은 색의 종류를 따로 나타내고, S는 색의 선명한 정도를, V는 밝기를 담당한다.


영상 처리 도구인 OpenCV에서 0~255 정수로 표현된 8비트 이미지를 일반 `COLOR_BGR2HSV` 방식으로 변환하면 각 채널은 정해진 범위를 가진다. 색상(H)은 색을 둥근 원으로 늘어놓은 360도 색상환을 절반으로 나눈 0 ~ 179 범위를 쓰고, 채도(S)와 명도(V)는 모두 0 ~ 255 범위를 쓴다. Photoshop 같은 도구에서는 H를 0 ~ 360으로 표기하므로 서로 값을 비교할 때 범위에 주의해야 한다. 또한 소수점이 있는 부동소수점 입력이나 `HSV_FULL` 변환은 표현 범위가 다르다([OpenCV Color Spaces Tutorial](https://docs.opencv.org/4.x/df/d9d/tutorial_py_colorspaces.html)).


세 채널을 같은 비율로 줄이는 이상적인 조건에서 픽셀 값을 직접 계산해 보면 밝기가 변해도 H가 그대로 유지되는 것을 확인할 수 있다. OpenCV는 파랑(B), 초록(G), 빨강(R) 순서로 값을 적으므로 순수한 빨강은 BGR `(0, 0, 200)`이다. 세 채널 가운데 최대값인 R이 200이고 최소값(min)이 0이므로 `V=200`이고, 채도는 `S=(200−0)/200×255=255`이다. 색상은 `H=60×(G−B)/(V−min)=60×0/200=0`이며, OpenCV는 이 값을 2로 나누어 0 ~ 179 범위에 맞추므로 `H=0`이 된다.


이 픽셀의 밝기를 절반으로 줄인 BGR `(0, 0, 100)`을 같은 식에 넣으면 `V=100`, `S=255`, `H=0`이 나온다. 밝기를 나타내는 V만 200에서 100으로 바뀌고 색의 종류인 H는 0으로 유지된다.

그림 1. 밝은 곳과 그늘에 있는 빨간 픽셀을 RGB 조건과 HSV 조건으로 걸러낸 결과 비교(직접 작성한 수치 예제).


순수한 빨강이 아닌 다른 색에서도 밝기만 같은 비율로 줄어들면 H 값은 변하지 않는다. 주황에 가까운 BGR `(0, 100, 200)`에서는 `R=200`, `G=100`, `B=0`이므로 `H=60×(100−0)/(200−0)=30`이다. OpenCV는 이 값을 절반으로 나누어 표현하므로 변환된 색상은 `H=15`가 된다. 밝기를 절반으로 줄인 BGR `(0, 50, 100)`에서도 `H=60×(50−0)/(100−0)=30`이 되어 OpenCV 기준 `H=15`를 그대로 유지한다.


![BGR (0, 100, 200)과 절반 밝기인 BGR (0, 50, 100)을 HSV로 변환했을 때 H=15와 S=255는 유지되고 V만 200에서 100으로 줄어드는 다이어그램](/images/notion/tech-k20/image-2.png)


그림 2. 세 채널을 같은 비율로 줄였을 때 BGR 값과 OpenCV HSV 변환 결과의 변화 비교(직접 계산한 수치 예제).


물론 이 계산은 세 채널의 비율이 정확히 유지되는 조건을 가정한 결과다. 값이 표현 범위를 넘어 잘리는 현상(clipping)이나 소수점을 정수로 반올림할 때 생기는 양자화 오차도 무시했다. 실제 조명은 밝기뿐만 아니라 색온도, 물체 표면의 반사, 카메라의 자동 보정까지 바꾸기 때문에 실제 촬영 영상에서는 H와 S 값도 함께 달라질 수 있다.


## OpenCV의 이진 마스크 생성


HSV에서 색상(H)으로 색의 종류를 구분할 수 있으므로, 이미지를 HSV로 변환하면 원하는 색 영역만 골라내는 마스크를 만들 수 있다. OpenCV에서는 먼저 `cv2.cvtColor()`로 BGR 이미지를 HSV로 변환한다. 그다음 `cv2.inRange()`를 호출해 지정한 범위 안에 드는 픽셀은 흰색(255), 나머지는 검은색(0)으로 채운 **이진 마스크**를 만든다. 이어서 `cv2.bitwise_and()`에 원본 이미지와 마스크를 넘기면 마스크 값이 255인 영역의 픽셀만 남는다.


```python
import cv2
import numpy as np

hsv = cv2.cvtColor(bgr_image, cv2.COLOR_BGR2HSV)

lower_blue = np.array([110, 50, 50])
upper_blue = np.array([130, 255, 255])

mask = cv2.inRange(hsv, lower_blue, upper_blue)
result = cv2.bitwise_and(bgr_image, bgr_image, mask=mask)
```


위 코드처럼 H 범위를 110 ~ 130으로 잡으면 OpenCV 기준으로 파란 계열만 통과한다. 이때 S와 V의 가장 낮은 값(하한)을 0이 아니라 50으로 둔 것은 채도가 너무 낮은 회색 톤이나 너무 어두운 픽셀이 섞이는 것을 막기 위해서다.


![BGR 이미지를 cvtColor로 HSV 변환하고 inRange로 이진 마스크를 만든 뒤 bitwise_and로 필터된 결과를 얻는 가로 흐름도](/images/notion/tech-k20/image-3.png)


그림 3. BGR 이미지를 HSV로 변환해 이진 마스크를 만들고 원본에 적용하는 OpenCV 색 필터링 과정.


찾으려는 BGR 색상이 OpenCV HSV에서 어떤 값에 대응하는지 모를 때는 한 픽셀짜리 배열을 만들어 변환해 보면 바로 확인할 수 있다.


```python
green_bgr = np.uint8([[[0, 255, 0]]])
green_hsv = cv2.cvtColor(green_bgr, cv2.COLOR_BGR2HSV)
# 결과: [[[60, 255, 255]]] — H가 60
```


변환 결과에서 나온 `H=60`을 기준으로 위아래 10 정도의 여유를 주면 `[50, 100, 100]` ~ `[70, 255, 255]`를 초록색 마스크 범위로 잡을 수 있다.


## 조명 변화와 채도, 명도 하한


앞서 파란색과 초록색 마스크를 만들 때 채도(S)와 명도(V)의 하한을 50이나 100으로 둔 것은 색상이 흔들리는 구간을 피하기 위해서다. HSV가 색상과 명도 조건을 따로 다루기 편하더라도 조명이 크게 바뀌면 마스크의 경계값(임계값)을 다시 확인해야 한다. 특히 명도(V)나 채도(S)가 낮아지는 구간에서는 H 값만 믿고 마스크를 만들기 어렵다.


거의 검은색에 가까울 만큼 V가 극단적으로 낮아지면 색상 정보 자체가 사라져 H 값이 불안정해진다. 흰색이나 회색에 가까운 파스텔 톤처럼 S가 낮은 경우에도 작은 픽셀 값 차이에 H가 크게 흔들린다. `cv2.inRange()`를 쓸 때 S 하한을 50이나 100으로 높여 잡는 관례는 이처럼 색상이 불안정한 구간을 미리 걸러내기 위한 것이다.

## 색 필터와 객체 인식의 경계


채도와 명도 하한을 조절해 색상이 안정적인 영역만 남기더라도, 색상 마스크만으로 이미지 속 물체를 바로 구별할 수는 없다. 예를 들어 이미지에서 노란색 조건을 걸면 택시뿐만 아니라 비슷한 색의 간판, 벽, 옷도 함께 선택된다. `cv2.inRange()`가 돌려주는 결과는 지정한 색상 범위에 들어온 픽셀의 모음일 뿐이어서, 선택된 픽셀이 찾으려는 물체인지 배경인지 가려내지 못한다.


이 때문에 색상 마스크는 물체를 찾아내는 전체 과정(객체 인식 파이프라인)에서 탐색할 후보 영역을 미리 줄이는 사전 작업(전처리 단계)으로 주로 쓰인다. 마스크에서 물체의 테두리(윤곽선)를 얻더라도 그것만으로 물체의 종류가 판정되지는 않는다. 물체를 구별하려면 모양, 위치, 학습된 특징 같은 추가 근거가 필요하다.


## 결론


RGB 색공간은 색의 종류와 밝기가 세 채널에 섞여 있어 조명이 어두워지면 같은 물체도 고정된 색상 조건에서 빠진다. 반면 HSV 색공간은 색상(H), 채도(S), 명도(V)를 나누어 다루며, 세 채널이 같은 비율로 줄어드는 조건에서는 밝기가 변해도 H 값이 유지됨을 픽셀 계산으로 확인했다. OpenCV에서는 이 성질을 이용해 이미지를 HSV로 바꾸고 `cv2.inRange()`로 원하는 색 영역만 남기는 이진 마스크를 만든다.


다만 채도(S)나 명도(V)가 너무 낮은 구간에서는 H 값이 크게 흔들리므로 하한을 높여 불안정한 픽셀을 걸러내야 한다. 또한 색상 마스크는 지정한 색 범위의 픽셀만 추려 낼 뿐 물체와 배경을 스스로 구별하지 못하므로 후보 영역을 줄이는 전처리 단계로 쓴다. 한편 빨간색은 색상환의 양 끝이 만나는 경계에 걸려 있어 H 범위를 `0 ~ 10`과 `170 ~ 179` 두 구간으로 나누어 다뤄야 한다. 이 빨간색 조건과 파스텔 톤 물체를 포함하려고 S 하한을 낮췄을 때 늘어나는 배경 잡음은 다음 실험에서 비교해 볼 생각이다.
