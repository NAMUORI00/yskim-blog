노래에서 보컬만 따로 꺼내는 음원 분리, 녹음된 목소리를 다른 음색으로 바꾸는 음성 변환, 문장을 소리 내어 읽는 음성 합성은 모두 오디오 파일을 결과로 내놓는다. 하지만 세 작업은 출발하는 입력 자료가 다르고, 처리 과정에서 끝까지 보존할 정보와 새로 만들어야 할 정보도 다르다. 이 글에서는 세 작업이 어떤 입력에서 출발해 어떤 중간 단계를 거쳐 시간에 따라 소리가 흔들리는 모양인 파형을 만드는지 비교한다.


## 음원 분리와 시간-주파수 마스크


세 작업 가운데 먼저 **음원 분리**(source separation)는 여러 소리가 합쳐진 오디오 파일 하나를 입력받는다. 여기서 보컬이나 악기처럼 성분별로 나뉜 개별 오디오 파일을 출력한다.


```plain text
입력:  vocals + drums + bass + other → mix.wav
출력:  vocals.wav, drums.wav, bass.wav, other.wav
```


음원 분리의 목표는 섞인 신호 안에 들어 있는 개별 성분을 추정하는 것이다. 흔히 쓰는 방식은 소리를 시간과 주파수 격자로 변환한 뒤, 각 칸(시간-주파수 빈)마다 특정 성분이 차지하는 비율인 마스크(mask)를 곱하는 방법이다. 예를 들어 어느 시간-주파수 칸에서 복소 스펙트럼 계수의 크기(진폭)가 0.8이고 실수 마스크 값이 0.7이면, 마스크를 곱한 뒤의 크기는 0.56이 된다.


이때 마스크가 0.7이라고 해서 원래 에너지의 70%를 가져왔다고 해석하면 틀린다. 신호의 에너지는 크기의 제곱에 비례하므로 원래 크기 0.8의 제곱 크기는 0.64다. 마스크를 곱한 크기 0.56의 제곱 크기는 0.3136이어서 원래 에너지의 49%에 그친다. 게다가 소리 물결의 시작 위치인 위상(phase) 차이와 성분 간섭 때문에, 분리된 각 소스의 에너지를 단순 합산해도 원래 혼합 에너지와 일치하지 않는다.


![스펙트럼 크기 0.8에 실수 마스크 0.7을 곱하면 추정 크기는 0.56이 되지만, 에너지를 나타내는 제곱 크기는 0.64에서 0.3136으로 줄어드는 계산 비교도](/images/notion/tech-k22/image-1.png)


그림 1. 시간-주파수 칸에서 실수 마스크(0.7)를 곱했을 때 스펙트럼 크기(0.56)와 제곱 크기(0.3136)의 차이.


대표적인 공개 분리 모델로 [Open-Unmix](https://github.com/sigsep/open-unmix-pytorch)가 있다. 이 모델은 시간 흐름을 양방향으로 따라가는 양방향 LSTM(장단기 메모리 신경망)으로 각 소스의 크기 스펙트로그램을 추정한다. 그 뒤 다채널 위너 필터링(Wiener filtering)을 거쳐 소리를 분리한다. 모든 분리 모델이 0에서 1 사이의 마스크만 예측하는 것은 아니며, 시간 영역의 파형을 직접 추정하는 구조도 있다.


어떤 구조를 쓰더라도 분리된 결과물에는 다른 악기 소리가 섞여 남거나 원래 소리가 일부 깎이는 왜곡(아티팩트)이 생길 수 있다. 따라서 혼합 신호를 성분별로 나눈다는 작업 목표와, 분리 결과가 섞이기 전의 원본 녹음을 그대로 복원한다는 주장은 구분해야 한다.


분리 품질은 모델이 추정한 소스와 실제 정답(참조 소스)을 비교하는 신호 대 왜곡비(SDR, Signal-to-Distortion Ratio) 계열 지표로 평가한다. 다만 시간 정렬이나 볼륨 스케일 보정, 오차 계산 조건에 따라 결과가 달라지므로 평가 도구 이름뿐 아니라 구체적인 계산 조건도 함께 확인해야 한다.


## 음성 변환과 화자 특징 교체


음원 분리가 이미 섞여 있는 신호에서 성분을 가르는 작업이라면, **음성 변환**(voice conversion)은 목소리의 주인을 바꾸는 작업이다. 원본 음성의 언어 내용(무슨 말을 했는지)은 그대로 두고 화자의 목소리 특성만 교체한다. 목표 화자의 목소리 샘플을 함께 넣어 주는 참조 음성 방식에서는 원본 음성과 목표 화자의 참조 음성을 입력으로 받는다. 별도로 학습된 화자 모델이나 화자 ID를 조건으로 넣는 방식도 있다.


```plain text
입력 1: 화자 A → "오늘 날씨가 좋다" (source.wav)
입력 2: 화자 B → 참조 음성 (reference.wav, 내용은 무관)
출력:   화자 B 목소리로 "오늘 날씨가 좋다" (converted.wav)
```


음성 변환은 원본에 없던 새로운 파형을 만들어야 한다. 화자 B가 해당 문장을 발화한 녹음이 없더라도, 모델이 화자 A의 발화 내용과 화자 B의 음색을 조합해 새로운 음성 신호를 생성한다. 공개 모델인 [kNN-VC](https://github.com/bshall/knn-vc)는 이 과정을 잘 보여 준다. 먼저 자기지도학습 음성 모델인 WavLM 인코더로 소스 음성(화자 A)과 참조 음성(화자 B)에서 각각 소리의 특징을 숫자로 묶은 특징 벡터를 추출한다. 그다음 소스 음성의 각 특징 벡터를 목표 참조 특징들 가운데 가장 가까운 k개 이웃(k-최근접 이웃)의 평균 벡터로 교체한다. 마지막으로 음향 특징을 오디오 파형으로 복원하는 신경망인 **보코더**(vocoder)를 거쳐 파형을 복원하며, kNN-VC에서는 HiFi-GAN 보코더를 사용한다.


![소스 음성과 참조 음성에서 각각 WavLM 인코더로 특징을 추출한 뒤 k-최근접 이웃 교체와 HiFi-GAN 보코더를 거쳐 변환 음성을 만드는 순서도](/images/notion/tech-k22/image-2.png)


그림 2. 소스 음성의 WavLM 특징을 참조 음성의 최근접 이웃 평균으로 교체하는 kNN-VC 음성 변환 흐름.


변환 결과의 품질은 두 축으로 평가한다. 원래의 언어 내용이 얼마나 또렷하게 보존되었는지 보는 명료도와, 음색이 목표 화자에 얼마나 가까워졌는지 보는 화자 유사도다. 한쪽 지표가 좋아졌다고 해서 다른 쪽도 함께 개선되었다고 볼 수는 없다. 입력 조건의 개수만으로 품질의 상충 관계를 설명하기보다, 같은 변환 결과에서 두 축을 따로 측정해 비교해야 한다.


## 음성 합성과 시간 정렬


음성 변환이 원본 오디오에서 말할 내용을 가져오는 것과 달리, **음성 합성**(text-to-speech, TTS)은 발화할 내용이 오디오가 아니라 텍스트로 주어진다. 참조 음성을 함께 넣어 화자나 발화 스타일을 조건으로 주더라도, 읽어야 할 내용 자체가 문자에서 출발한다는 점은 변하지 않는다.


```plain text
입력: "내일 비가 올 수 있습니다" (텍스트 문자열)
출력: 해당 문장을 읽어주는 synthesized.wav
```


딱딱 끊어지는 불연속적인 문자 기호에서 연속적인 소리 파형을 바로 만들기는 어렵기 때문에, 전통적인 신경망 TTS는 보통 두 단계로 나누어 처리한다. 첫 단계에서는 텍스트를 시간 흐름에 따른 주파수 에너지 분포인 **멜 스펙트로그램**(mel spectrogram)으로 변환한다. 둘째 단계에서는 보코더가 이 멜 스펙트로그램을 실제 소리 파형으로 바꾼다. 예를 들어 [Tacotron 2](https://arxiv.org/abs/1712.05884)는 멜 예측 신경망과 수정된 WaveNet 보코더를 결합한 모델이다. 앞서 본 HiFi-GAN은 다른 보코더 선택지이므로 원래 Tacotron 2의 구성과는 구분해야 한다.


![텍스트가 텍스트 인코더를 거쳐 멜 스펙트로그램으로 변환되고 보코더를 통해 파형 출력으로 이어지는 음성 합성 개념도](/images/notion/tech-k22/image-3.png)


그림 3. 멜 스펙트로그램과 보코더를 사용하는 음성 합성 경로. 직접 작성한 설명용 개념도.


음성 변환과 음성 합성은 둘 다 마지막 단계에서 보코더를 사용하지만, 앞단에서 다루는 시간 정보의 조건이 다르다. 음성 변환에서는 원본 음성의 발화 타이밍과 억양(운율) 뼈대를 그대로 가져올 수 있다. 반면에 음성 합성에서는 발화 속도, 쉼, 억양까지 모두 텍스트로부터 추론해야 한다. 따라서 문자 시퀀스(글자 나열)와 멜 스펙트로그램의 시간 칸(프레임)을 맞추는 정렬(alignment)을 별도로 풀어야 한다. 합성 모델 안에 읽을 글자를 찾는 어텐션(attention) 구조나 발음 길이를 재는 길이 예측기(duration predictor)가 들어가는 이유가 여기에 있다.


## 세 작업의 입출력과 중간 표현 비교


지금까지 본 세 작업을 입력과 출력, 핵심 연산을 기준으로 나란히 놓으면 구조의 차이가 드러난다.


| 작업    | 입력                   | 출력       | 핵심 연산                   |
| ----- | -------------------- | -------- | ----------------------- |
| 음원 분리 | 혼합 오디오               | 추정 소스 N개 | 마스크, 스펙트럼, 파형 추정 등      |
| 음성 변환 | 소스 음성 + 목표 화자 조건     | 변환 음성    | kNN-VC 예에서는 특징 교체       |
| 음성 합성 | 텍스트 + 선택적 화자와 스타일 조건 | 합성 음성    | 음향 특징 또는 오디오 토큰이나 파형 생성 |

세 작업 모두 최종적으로는 모델이 결과 파형을 추정하므로, 신호를 새로 생성하는지 여부만으로는 구분하기 어렵다. 분리는 혼합 신호의 성분을, 변환은 원본 발화와 화자 조건의 결합을, 합성은 텍스트의 발화 표현을 다룬다. 이 차이는 모델 내부에서 입력과 출력 사이를 잇는 **중간 표현**(intermediate representation)에 그대로 반영된다.


음원 분리의 마스크는 각 시간-주파수 칸이 어느 소스에 속하는지를 나타낸다. 앞서 설명을 위해 합이 1이 되는 상보적인 0~1 마스크를 예로 들었지만, 실제 출력 제약 조건은 모델마다 다르다. 음성 변환에서 쓰는 WavLM 특징은 언어 내용과 화자 특성이 함께 남아 있을 수 있는 학습 표현이므로, 화자와 무관한 언어 표현을 발라내는 것이 변환의 전제가 된다. 음성 합성의 멜 스펙트로그램은 어떤 주파수 에너지가 어느 시점에 나타나야 하는지를 연속된 값으로 표현한다.


## 결론


음원 분리, 음성 변환, 음성 합성은 모두 오디오 파형을 결과로 내놓지만, 출발하는 입력 조건에 따라 중간 표현이 보존할 정보와 새로 만들 정보의 경계를 다르게 잡는다. 따라서 음성 변환과 음성 합성에서 같은 보코더를 사용하더라도, 앞 단계에서 넘어오는 입력 표현의 분포가 다르면 최종 품질에 영향을 준다. 보코더 이름이 같다고 해서 파형을 복원하는 처리 전체가 같다고 볼 수는 없다.


이 글에서는 세 작업의 입력 조건과 중간 표현, 평가 기준의 차이를 비교했다. 변환과 합성에서 보코더를 공유할 때 입력 분포와 학습 조건이 어떻게 달라지는지는 아직 확인하지 않았으며, 추가 비교 대상으로 남는다. 음원 분리 뒤에 음성 변환을 이어 붙이는 파이프라인에서 앞 단계의 분리 왜곡(아티팩트)이 뒷단계의 변환 출력으로 어떻게 넘어가는지도 이어서 확인할 문제다.
