음원 분리, 음성 변환, 음성 합성을 입력과 출력 기준으로 정리했다. 보컬을 꺼내는 작업, 녹음된 목소리를 바꾸는 작업, 문장을 읽는 작업은 모두 오디오를 만들지만 출발 자료와 보존할 정보가 다르다. 이 차이를 파일 흐름에 맞춰 비교했다.


## 음원 분리: 섞인 신호를 성분으로 나누기


음원 분리(source separation)의 입력은 여러 소리가 합쳐진 하나의 오디오 파일이고, 출력은 성분별로 분리된 개별 파일이다.


```javascript
입력:  vocals + drums + bass + other → mix.wav
출력:  vocals.wav, drums.wav, bass.wav, other.wav
```


이 작업의 목표는 혼합에 포함된 성분을 추정하는 데 있다. 한 가지 설명 방법은 시간, 주파수별 마스크를 적용하는 것이다. 예를 들어 복소 스펙트럼 계수의 크기가 0.8이고 실수 마스크가 0.7이면 적용 후 크기는 0.56이 된다.


이를 에너지의 70%를 배분했다고 해석하면 틀린다. 제곱 크기는 0.3136이고, 위상과 성분 간 간섭 때문에 각 소스 에너지의 합도 혼합 에너지와 단순히 일치하지 않는다.


[Open-Unmix](https://github.com/sigsep/open-unmix-pytorch)는 양방향 LSTM으로 소스의 크기 스펙트로그램을 추정하고, 다채널 위너 필터링을 거쳐 분리하는 예다.


모든 분리 모델이 0~1 마스크를 직접 예측하는 것은 아니며 파형을 직접 추정하는 구조도 있다. 분리 결과에 다른 악기의 소리가 남거나 원래 소리가 훼손될 수 있어서, 목표가 분해라는 사실과 결과가 원본을 정확히 보존한다는 주장은 구분해 두었다.


분리 평가는 추정 소스와 참조 소스를 비교하는 SDR 계열 지표 등을 사용한다. 정렬, 스케일 보정, 오차 분해 조건에 따라 의미가 달라져, 도구 이름뿐 아니라 계산 조건을 함께 비교할 필요가 있다.


## 음성 변환: 말의 내용은 유지하고 화자를 교체하기


음성 변환(voice conversion)은 원본 음성의 언어 내용을 유지하면서 화자 특성 등을 바꾸려는 작업이다. 아래 참조 음성 방식에서는 원본과 목표 화자의 음성을 함께 받는다. 별도 학습된 화자 모델이나 화자 ID를 쓰는 방식도 있다.


```javascript
입력 1: 화자 A → "오늘 날씨가 좋다" (source.wav)
입력 2: 화자 B → 참조 음성 (reference.wav, 내용은 무관)
출력:   화자 B 목소리로 "오늘 날씨가 좋다" (converted.wav)
```


음원 분리와 달리 여기서는 원본에 없던 파형을 만들어야 한다. 화자 B가 해당 문장을 발화한 녹음이 없어도, 모델이 A의 발화 내용과 B의 음색을 조합해 새 신호를 생성한다.


[kNN-VC](https://github.com/bshall/knn-vc)의 접근이 이 과정을 잘 보여준다. WavLM 인코더로 소스 음성에서 추출한 특징 벡터 각각을 타깃 참조 특징의 k-최근접 이웃 평균으로 교체하고, HiFi-GAN 보코더가 교체된 특징 시퀀스를 파형으로 복원한다.


변환 품질은 두 축으로 갈린다. 언어 내용이 얼마나 보존되었는가(명료도)와 음색이 타깃 화자에 얼마나 근접한가(화자 유사도)인데, 한쪽 지표가 좋아졌다고 다른 쪽도 개선되었다고 볼 수는 없다. 입력 개수만으로 품질의 상충을 설명하기보다 같은 변환 결과에서 두 축을 따로 평가할 필요가 있다.


## 음성 합성: 텍스트에서 파형까지


음성 합성(text-to-speech, TTS)에서는 발화할 내용이 텍스트에서 주어진다. 참조 음성으로 화자나 스타일을 조건화하더라도 이 점은 유지된다.


```javascript
입력: "내일 비가 올 수 있습니다" (텍스트 문자열)
출력: 해당 문장을 읽어주는 synthesized.wav
```


이산적인 문자 기호에서 연속적인 파형을 만들어야 하므로, 전통적인 신경망 TTS를 설명하는 한 경로는 두 단계로 나눌 수 있다. 첫 단계에서 텍스트를 멜 스펙트로그램으로 변환하고, 둘째 단계에서 보코더가 멜 스펙트로그램을 실제 파형으로 바꾼다.


[Tacotron 2](https://arxiv.org/abs/1712.05884)는 멜 예측망과 수정된 WaveNet 보코더를 결합했다. HiFi-GAN은 다른 보코더 선택지이며, 원래 Tacotron 2의 구성으로 섞어 읽지 않기로 했다.

음성 변환도 마지막에 보코더를 사용하지만, 변환에서는 원본 음성의 타이밍과 운율 뼈대를 가져올 수 있다. 합성에서는 발화 속도, 쉼, 억양까지 텍스트로부터 추론해야 하므로 텍스트와 멜 프레임 사이의 정렬(alignment)을 별도로 풀어야 한다. 이것이 합성 모델에 어텐션 메커니즘이나 duration predictor가 들어가는 이유다.

세 작업을 나란히 놓으면 패턴이 드러난다.


| 작업    | 입력                   | 출력       | 핵심 연산                   |
| ----- | -------------------- | -------- | ----------------------- |
| 음원 분리 | 혼합 오디오               | 추정 소스 N개 | 마스크, 스펙트럼, 파형 추정 등      |
| 음성 변환 | 소스 음성 + 목표 화자 조건     | 변환 음성    | kNN-VC 예에서는 특징 교체       |
| 음성 합성 | 텍스트 + 선택적 화자와 스타일 조건 | 합성 음성    | 음향 특징 또는 오디오 토큰이나 파형 생성 |

세 작업 모두 결과 파형을 추정하므로 생성 여부만으로 구분하기는 어렵다. 분리는 혼합 성분, 변환은 원본 발화와 화자 조건, 합성은 텍스트의 발화 표현을 중심으로 읽었다.


음성 변환은 분리처럼 오디오를 입력받고 합성처럼 조건에 맞는 신호를 만든다. 입력의 종류와 출력 목표를 나누어 보니 공유하는 구성 요소와 다른 평가 기준을 정리할 수 있었다.


## 작업별 중간 표현


세 작업 모두 내부에서 스펙트로그램이나 임베딩 같은 중간 표현을 거치지만, 각 중간 표현이 담는 정보의 성격이 다르다.


음원 분리의 마스크는 "각 시간-주파수 빈이 어느 소스에 속하는가"를 인코딩한다. 여기서는 설명하기 쉬운 상보적인 0~1 마스크를 예로 들었으며, 출력 제약은 모델마다 다르다. 음성 변환에서 WavLM 특징은 언어 내용과 화자 특성이 함께 남을 수 있는 학습 표현이다.


화자에 무관한 언어 표현을 추출하는 것이 변환의 핵심 전제다. 음성 합성에서 멜 스펙트로그램은 "어떤 주파수 에너지가 어느 시점에 있어야 하는가"를 연속 값으로 표현한다.


중간 표현은 보존할 정보와 바꿀 정보의 경계를 담는다. 같은 보코더를 사용해도 입력 표현의 분포가 달라지면 품질에 영향을 줄 수 있다. 보코더 이름만으로 처리 전체가 같다고 보기 어려운 지점이다.


## 후속 검토


변환과 합성에서 보코더를 공유할 때의 입력 분포와 학습 조건은 추가 비교 대상으로 남았다. 음원 분리 뒤 변환을 연결하는 경우에는 앞 단계의 아티팩트가 출력으로 어떻게 이어지는지도 함께 살펴볼 내용이다.
