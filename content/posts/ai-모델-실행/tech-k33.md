## 문장이 숫자로 바뀌는 첫 단계


‘나는 밥을 먹었다’라는 짧은 문장으로 토큰화 이후의 처리 흐름을 정리했다. 텍스트를 단위별 정수 번호로 바꾸고 임베딩과 레이어에 넣는 과정이다. 숫자 목록의 생성과 모델 내부의 표현 변화를 나누어 살펴봤다.


토큰은 글자, 단어, 하위 단어 등 토크나이저가 정한 단위로 나뉜다. BPE(Byte Pair Encoding)는 말뭉치에서 자주 이어지는 기호 쌍을 합쳐 어휘를 만드는 방식이다. 출발 기호를 문자로 잡을 수도 있고, byte-level BPE처럼 바이트로 잡을 수도 있다.


BPE의 초기 어휘는 구현에 따라 문자 또는 바이트 등으로 구성된다. 자주 쓰이는 단어는 통째로 하나의 토큰이 되고, 드문 단어는 여러 조각으로 쪼개진다. 새 단어를 하위 토큰으로 표현할 수 있지만, 기본 어휘에 없는 문자를 처리하는 방식은 토크나이저마다 다르다.


아래는 흐름을 설명하려고 만든 분할과 임의의 ID다. 실제 토크나이저 실행 결과가 아니며, 같은 글자 수라도 모델마다 토큰 수가 달라진다.


```javascript
"나는 밥을 먹었다"
→ ["나는", " 밥", "을", " 먹", "었다"]
→ [8271, 14502, 2319, 9847, 6120]
```


같은 문장이라도 토크나이저에 따라 쪼개지는 위치와 토큰 수가 달라진다. 모델이 보는 입력은 이 정수 배열이다.


## 정수에서 벡터로: 임베딩


토큰 ID가 8271이라는 사실만으로는 "나는"이 어떤 역할인지 알 수 없다. 정수는 크기 비교가 무의미한 라벨일 뿐이다. **임베딩**(embedding)은 각 토큰 ID를 고정 길이의 실수 벡터로 변환하는 단계다.


어휘 크기가 50,000이고 임베딩 차원이 4라면, 임베딩 테이블은 50,000행 × 4열 크기의 행렬이다. 토큰 ID 8271은 이 행렬의 0부터 세는 인덱스 8271의 행을 꺼내서 `[0.12, −0.34, 0.56, 0.01]` 같은 벡터가 된다.


임베딩 값은 학습 과정에서 조정된다. 의미가 비슷한 표현의 방향은 학습 데이터와 문맥에 따라 달라진다. 이때의 유사도는 사전 정의된 규칙보다 학습 데이터와 목적에 연결해 읽을 대상이다.


입력 문장의 토큰이 5개이고 임베딩 차원이 4라면, 이 단계의 출력은 5 × 4 크기의 행렬이 된다. 각 행이 토큰 하나의 벡터 표현이다.


## 토큰끼리 서로를 참조하는 방식: attention


임베딩을 거친 토큰 벡터들이 나란히 놓인다. 여기서 각 토큰이 다른 토큰들을 얼마나 참조할지 결정하는 과정이 **attention**이다.


"먹"이라는 토큰의 의미를 파악할 때 "밥"이라는 맥락이 "나는"보다 더 중요할 수 있다. attention은 이 관계를 숫자로 표현한다. 각 토큰 벡터에서 **질의**(Query, Q), **키**(Key, K), **값**(Value, V) 세 벡터를 만든 뒤, 질의와 키의 내적으로 유사도를 구하고 softmax로 정규화하면 가중치가 된다.


토큰 세 개, 차원 2인 간단한 경우로 계산해 보았다. 아래 Q, K 값은 개념 설명을 위해 구성한 예시다.


| 토큰 | Q 벡터   | K 벡터   |
| -- | ------ | ------ |
| 나는 | [1, 0] | [0, 1] |
| 밥  | [0, 1] | [1, 1] |
| 먹  | [1, 1] | [1, 0] |


"먹"의 Q = [1, 1]로 각 토큰의 K와 내적을 구하면:

- 먹 → 나는: 1×0 + 1×1 = **1**
- 먹 → 밥: 1×1 + 1×1 = **2**
- 먹 → 먹: 1×1 + 1×0 = **1**

이 점수를 √d(d는 차원 수, 여기서 √2 ≈ 1.41)로 나누면 약 0.707, 1.414, 0.707이 된다. 여기에 softmax를 적용하면 가중치가 약 **0.248, 0.503, 0.248**가 된다.


"먹"은 "밥"에 가장 높은 가중치(약 0.503)를 부여하고, "나는"과 자기 자신에는 각각 약 0.248를 부여한다. 이 가중치로 각 토큰의 V 벡터를 가중합하면 "먹"의 새로운 표현이 만들어진다.


실제 모델에서는 이런 attention을 여러 개 병렬로 수행하는 multi-head attention을 사용한다. head마다 다른 투영을 사용하므로 서로 다른 관계를 표현할 여지가 생긴다. 각 head의 역할은 학습 과정에서 형성되며, 모델의 판단 이유를 분석할 때는 attention 가중치와 다른 근거를 함께 살펴야 한다.

## 레이어를 쌓아 표현을 다듬기


attention을 한 번 거친 벡터는 피드포워드 신경망을 통과한다. attention이 토큰 간 관계를 반영하는 단계라면, 피드포워드는 각 토큰의 표현을 독립적으로 변환하는 단계다. 이 두 과정(attention과 피드포워드)을 묶은 것이 하나의 **레이어**(layer)다.


레이어는 앞에서 조합한 표현을 다시 변환한다. 전역 attention은 첫 레이어부터 마스크가 허용한 모든 위치를 참조할 수 있어, 깊이를 참조 범위가 한 칸씩 늘어나는 과정으로 해석하지 않았다.


attention과 피드포워드의 각 하위층에는 잔차 연결과 정규화가 함께 사용되며 정규화 위치는 구조마다 다르다. 아래는 pre-norm 형태의 설명용 블록이다. 토큰의 순서를 나타내는 정보도 필요하고, 이를 입력에 더하거나 Q/K에 위치 변환을 적용하는 등 모델별 방식이 다르다. 자동회귀 언어 모델에서는 현재 위치가 미래 토큰을 보지 못하도록 causal mask를 적용한다.

그림 2. 정규화를 하위층 앞에 놓은 pre-norm 블록의 설명용 구조. 더하기 노드로 입력이 우회하는 잔차 경로를 표시했다. 핵심 연산 흐름을 중심으로 단순화한 그림이다. 출처: Transformer 블록의 연산 관계를 직접 구성.


## 문맥 길이라는 제약


밀집 self-attention에서 길이가 n이면 한 head의 점수 행렬은 n × n이다. n = 4,096일 때 16,777,216개 점수가 생긴다. causal mask를 적용하면 미래 위치는 제외되지만 기본 연산 규모는 여전히 제곱에 비례한다. 이 계산은 전체 입력을 처리하는 경우이며, KV 캐시를 쓰며 다음 토큰 하나를 생성하는 단계와 구분해야 한다.


다만 전체 메모리 사용량이 언제나 n²로 늘어난다고 단정하면 구현 차이를 놓친다. [FlashAttention 원논문](https://arxiv.org/abs/2205.14135)은 큰 점수 행렬을 GPU 메모리에 통째로 저장하는 부담을 줄이도록 계산 순서를 바꾼다. 밀집 attention의 연산 관계를 유지하면서 저장과 전송 비용을 다룬 접근이다.


문맥 길이에는 계산 자원, 위치 표현, 학습 길이, 실행 설정이 함께 관여한다. 긴 입력을 지원해도 먼 근거를 정확히 사용한다는 보장은 없다. 입력을 줄이는 경우에는 토큰 수와 잘려 나간 근거를 함께 확인할 항목으로 정리했다.


## 추가로 정리할 내용


토큰 ID에서 임베딩으로, 이어 attention과 레이어의 표현으로 바뀌는 경로를 따라갔다. 각 단계의 입력 형태를 나누니 학습과 출력 제한을 더 살펴볼 위치도 구체화됐다.


Q, K, V 투영 가중치에 기울기 갱신이 적용되는 과정과 GPT 계열의 masked attention 제약은 후속 주제다. 이번에 계산한 attention에 학습 규칙과 미래 위치 제한을 각각 연결하는 내용이다.
