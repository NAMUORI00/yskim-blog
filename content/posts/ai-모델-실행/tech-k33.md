언어 모델에 `"나는 밥을 먹었다"`라는 문장을 넣으면 모델은 글자를 그대로 읽지 않는다. 컴퓨터는 숫자만 계산할 수 있어서 문장을 정해진 단위로 쪼개 정수 번호를 붙이고, 그 번호에 해당하는 실수 묶음을 꺼내 여러 계산 층으로 넘긴다. 입력 문장이 어떤 형태의 숫자로 바뀌어 모델 내부를 통과하는지 작은 계산 예제로 단계마다 따라간다.


## 토큰 분할과 정수 번호


문장을 숫자로 바꾸는 첫 단계는 문자열을 작은 조각으로 나누고 각 조각에 고유한 정수 번호를 붙이는 일이다. 다음 예제는 처리 흐름을 보여 주기 위해 문장을 임의로 나눈 조각과 번호다. 실제 분할 도구의 실행 결과는 아니며, 모델이 처음 받는 입력은 문자열이 아니라 맨 아래의 정수 배열이다.


```plain text
"나는 밥을 먹었다"
→ ["나는", " 밥", "을", " 먹", "었다"]
→ [8271, 14502, 2319, 9847, 6120]
```


이처럼 텍스트를 쪼갠 단위를 **토큰**(token), 각 토큰에 붙인 정수 번호를 **토큰 ID**라 부른다. 문장을 글자나 단어, 또는 단어보다 작은 하위 단어(subword) 가운데 어디를 기준으로 나눌지는 분할 도구인 토크나이저가 정한다. 같은 문장이라도 모델의 토크나이저에 따라 쪼개지는 위치와 토큰 수가 달라진다.


대표적인 하위 단어 분할 방식인 BPE(Byte Pair Encoding)는 처음에 문자나 바이트(byte-level BPE)로 초기 어휘를 둔다. 그다음 많은 글을 모아 둔 말뭉치에서 자주 나란히 등장하는 기호 쌍을 차례로 합쳐 어휘 사전을 만든다. 그래서 자주 쓰이는 단어는 통째로 토큰 하나가 되고, 드문 단어나 처음 보는 단어는 여러 하위 토큰으로 쪼개진다. 기본 어휘에 없는 문자를 다루는 방식도 토크나이저 구현마다 다르다.


## 임베딩 테이블과 초기 벡터


앞 단계에서 얻은 토큰 ID가 `8271`이라는 사실만으로는 `"나는"`이 문장에서 어떤 역할을 하는지 알 수 없으므로, 각 번호를 계산 가능한 실수 묶음으로 바꾸어야 한다. 여기서 정수는 사전에 붙인 번호표일 뿐이어서 숫자의 크고 작음에 의미가 없다. 이 토큰 ID를 `[0.12, −0.34, 0.56, 0.01]`처럼 고정된 길이의 실수 벡터로 바꾸는 단계가 **임베딩**(embedding)이다.


어휘 크기가 50,000이고 벡터 하나를 이루는 실수 개수인 임베딩 차원이 4라면, 임베딩 테이블은 50,000행 × 4열 크기의 행렬이 된다. 토큰 ID `8271`이 들어오면 0부터 세는 인덱스 8271의 행을 그대로 꺼내 `[0.12, −0.34, 0.56, 0.01]` 같은 4차원 벡터로 바꾼다.


이 행렬의 실수 값들은 모델이 학습하는 동안 조금씩 조정된다. 의미가 비슷한 표현이 가리키는 방향은 학습 데이터와 문맥에 따라 달라진다. 따라서 벡터 사이의 유사도는 사람이 미리 정한 규칙이 아니라 학습 데이터와 목적에 연결해 읽어야 한다.


입력 문장이 토큰 5개로 나뉘고 임베딩 차원이 4라면, 임베딩 단계를 거친 출력은 그림 1처럼 5 × 4 크기의 행렬이 된다. 이 행렬의 행 하나가 토큰 하나의 초기 벡터 표현이다.

그림 1. 문장이 5개의 토큰 ID로 나뉜 뒤 50,000 × 4 임베딩 테이블에서 각 행을 꺼내 5 × 4 입력 행렬을 만드는 과정.


## 어텐션 가중치와 문맥 계산


임베딩 테이블에서 꺼낸 초기 벡터들은 아직 각 토큰의 정보만 따로 담고 있으므로, 문장 안의 다른 토큰과 어떻게 연결되는지 계산해 문맥을 반영해야 한다. 예를 들어 `"먹"`이라는 토큰의 의미를 파악할 때는 `"나는"`보다 목적어인 `"밥"`이라는 맥락이 더 중요할 수 있다. 이처럼 각 토큰이 문장 안의 다른 토큰을 얼마나 참조해 문맥을 반영할지 숫자로 계산하는 과정이 **어텐션**(attention)이다.


어텐션 계산을 위해 모델은 각 토큰 벡터에서 **질의**(Query, Q), **키**(Key, K), **값**(Value, V) 세 벡터를 만든다. 기준 토큰의 질의와 각 토큰의 키에서 같은 자리의 숫자를 곱해 더하는 내적을 구하면 두 벡터의 유사도 점수가 나온다. 이 점수를 전체 합이 1인 비율로 바꾸는 소프트맥스(softmax)로 정규화하면 참조 가중치가 된다.


토큰 3개, 차원 수 2인 간단한 경우로 직접 계산해 봤다. 아래 표의 Q와 K 벡터는 개념을 설명하기 위해 임의로 구성한 값이다.


| 토큰 | Q 벡터   | K 벡터   |
| -- | ------ | ------ |
| 나는 | [1, 0] | [0, 1] |
| 밥  | [0, 1] | [1, 1] |
| 먹  | [1, 1] | [1, 0] |


`"먹"`의 Q = `[1, 1]`로 각 토큰의 K와 내적을 구하면 점수는 다음과 같다.

- 먹 → 나는: 1×0 + 1×1 = 1
- 먹 → 밥: 1×1 + 1×1 = 2
- 먹 → 먹: 1×1 + 1×0 = 1

이 점수를 √d(d는 차원 수, 여기서 √2 ≈ 1.41)로 나누면 각각 약 `0.707`, `1.414`, `0.707`이 된다. 여기에 softmax를 적용하면 합이 1인 가중치 약 0.248, 0.503, 0.248을 얻는다.


결과적으로 `"먹"`은 `"밥"`에 가장 높은 가중치(약 `0.503`)를 주고, `"나는"`과 자기 자신에게는 각각 약 `0.248`을 준다. 이 가중치를 세 토큰의 V 벡터에 각각 곱해 더하는 가중합을 구하면 문맥이 반영된 `"먹"`의 새로운 표현이 만들어진다.


실제 모델은 이런 어텐션을 여러 개 병렬로 수행하는 멀티헤드 어텐션(multi-head attention)을 사용한다. 계산 단위인 헤드(head)마다 토큰 벡터를 Q, K, V로 변환하는 투영을 서로 다르게 쓰므로 토큰 사이의 여러 관계를 동시에 표현할 여지가 생긴다. 다만 각 헤드의 역할은 학습 과정에서 형성되므로, 모델의 판단 이유를 분석할 때는 어텐션 가중치만 보지 않고 다른 근거도 함께 확인해야 한다.


![토큰 벡터에서 Q, K, V 투영을 거쳐 유사도 점수와 위치 마스크, 소프트맥스, 가중합으로 새 표현을 만드는 어텐션 연산 순서도](/images/notion/tech-k33/image-2.png)


그림 2. 어텐션 헤드 하나의 연산 흐름으로, 마스크로 참조 가능한 위치를 제한한 뒤 허용된 위치의 점수에서 가중치를 구해 V 벡터를 가중합한다. 출처: Transformer 원논문을 바탕으로 직접 구성.


## 트랜스포머 레이어와 블록 구조


어텐션을 한 번 거친 벡터는 이어서 피드포워드 신경망을 통과하며 하나의 블록 안에서 다시 변환된다. 어텐션이 토큰 사이의 관계를 반영하는 단계라면, 피드포워드 신경망은 각 토큰의 표현을 독립적으로 변환하는 단계다. 어텐션과 피드포워드 두 과정을 하나로 묶은 단위가 트랜스포머의 **레이어**(layer)다.


모델은 이 레이어를 여러 겹 쌓아 앞 층에서 조합한 표현을 다시 변환한다. 이때 문장 전체를 살피는 전역(global) 어텐션은 첫 번째 레이어부터 참조 범위를 제한하는 마스크가 허용한 모든 위치를 한꺼번에 참조할 수 있다. 따라서 레이어가 깊어진다는 것은 참조 범위가 한 칸씩 넓어지는 과정이 아니라, 이미 참조한 문맥 표현을 거듭 조합해 다듬는 과정에 가깝다.


어텐션과 피드포워드 각 하위층에는 원래 입력을 출력에 그대로 더하는 잔차 연결(residual connection)을 둔다. 여기에 숫자 값의 분포를 일정하게 맞추는 정규화(normalization)도 함께 쓴다. 정규화를 두는 위치는 모델 구조마다 다른데, 그림 3은 하위층 연산 앞에 정규화를 놓은 사전 정규화(pre-norm) 블록이다.


![입력 표현 x가 정규화와 어텐션, 잔차 덧셈을 거친 뒤 다시 정규화와 피드포워드, 잔차 덧셈을 통과해 다음 블록 입력으로 이어지는 구조도](/images/notion/tech-k33/image-3.png)


그림 3. 정규화를 각 하위층 앞에 놓은 사전 정규화(pre-norm) 블록의 구조로, 입력이 하위층을 우회해 더해지는 잔차 연결 경로를 함께 표시했다. 출처: Transformer 블록의 연산 관계를 직접 구성.


또한 어텐션 연산 자체는 토큰의 순서를 구분하지 못하므로, 입력 임베딩에 위치 정보를 더하거나 Q와 K에 위치 변환을 적용해 순서 정보를 넣어 준다. 앞 토큰들을 보고 다음 토큰을 차례로 생성하는 모델을 자동회귀(autoregressive) 언어 모델이라 한다. 이런 모델에서는 현재 위치가 뒤에 올 미래 토큰을 미리 보지 못하도록 가리는 **인과 마스크**(causal mask)를 적용한다.


## 문맥 길이와 연산 규모


레이어 안에서 모든 토큰 쌍의 어텐션을 계산할 때는 입력 문장이 길어질수록 계산해야 할 점수 행렬의 크기가 급격히 커진다. 모든 토큰 쌍을 계산하는 밀집 자기 어텐션(dense self-attention)에서 입력 길이가 n이면 헤드 하나의 점수 행렬 크기는 n × n이 된다. 예를 들어 n = 4,096일 때 헤드 하나에서만 16,777,216개의 점수가 생긴다. 그림 4처럼 인과 마스크를 적용해 미래 위치를 제외하더라도 기본 연산 규모는 여전히 입력 길이의 제곱에 비례한다. 물론 이 계산은 입력 전체를 한 번에 처리하는 단계에 해당한다. 이전 토큰의 K와 V를 임시 저장소인 캐시(KV cache)에 담아 두고 다음 토큰 하나를 생성하는 단계와는 구분해야 한다.


![질의와 키 위치로 이루어진 행렬에서 대각선 아래는 참조가 허용되고 대각선 위 미래 위치는 마스크로 제외되며 길이 4096일 때 16777216개의 점수가 생기는 개념도](/images/notion/tech-k33/image-4.png)


그림 4. 인과 마스크(causal mask)가 적용된 어텐션 점수 행렬의 구조와 입력 길이 n에 따라 제곱으로 늘어나는 전체 점수 규모.


그렇다고 전체 메모리 사용량이 언제나 n²으로 늘어난다고 단정하면 구현 차이를 놓치기 쉽다. 예를 들어 [FlashAttention 원논문](https://arxiv.org/abs/2205.14135)은 큰 점수 행렬을 GPU 메모리에 통째로 저장하는 부담을 줄이려고 계산 순서를 바꾼다. 밀집 어텐션의 연산 결과는 그대로 유지하면서 메모리 저장과 전송 비용을 줄인 접근이다.


결국 모델이 다룰 수 있는 문맥 길이에는 계산 자원과 위치 표현 방식, 학습할 때 쓴 문맥 길이, 실행 설정이 함께 관여한다. 또한 모델이 긴 입력을 지원한다고 해서 문맥 속의 먼 근거를 언제나 정확히 사용한다는 보장은 없다. 입력을 줄여야 할 때는 전체 토큰 수와 잘려 나간 근거를 함께 확인해야 한다.


## 결론


언어 모델에 들어간 입력 문장은 토큰 ID를 거쳐 임베딩 벡터 행렬로 바뀌고, 어텐션과 피드포워드 레이어를 통과하며 문맥이 반영된 표현으로 다듬어진다. 이 글에서는 작은 계산 예제로 토큰 분할과 임베딩 조회, 어텐션 가중치 계산을 따라가고, 레이어가 깊어질 때의 블록 구조와 입력 길이에 따른 연산 규모를 확인했다.


다만 각 단계가 주고받는 데이터 형태와 한 번의 계산 흐름만 다루었을 뿐, 모델이 가중치를 스스로 학습하는 과정과 생성 시점의 마스크 제약은 아직 구체적으로 확인하지 않았다. Q, K, V 투영 가중치를 조정하는 기울기 갱신과 미래 위치를 제한하는 GPT 계열의 마스크드 어텐션(masked attention) 제약은 후속 주제로 다룬다.
