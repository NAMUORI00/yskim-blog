## 문장 비교를 숫자로 해야 하는 이유


텍스트를 벡터로 표현하는 방식을 정리하며 내적과 코사인 유사도를 계산해 봤다. ‘엔진 점검’과 ‘동력 장치 정비’처럼 단어가 다른 문장을 비교하려면, 좌표가 만들어지는 규칙과 그 좌표의 유사도를 나누어 읽을 필요가 있었다.


임베딩은 텍스트를 숫자 배열인 벡터로 바꾸는 표현이다. 코사인 유사도는 두 벡터의 방향을 비교한다. 높은 점수가 원문의 의미적 유사성과 얼마나 연결되는지는 벡터를 만든 방식에 달려 있다.


검색, 분류, 추천 시스템 어디서든 이 변환이 출발점 역할을 한다. 변환 방식에 따라 같은 문장 쌍의 유사도가 크게 달라지는데, 해시 기반 변환과 학습 기반 변환이 어떻게 다른 결과를 내는지를 작은 예제로 비교해 두었다.


## 2차원 벡터로 코사인 유사도 따라가기


실제 임베딩은 수백 차원이지만, 원리 자체는 2차원에서 똑같이 확인할 수 있다. 세 문장이 아래 2차원 벡터로 변환되었다고 가정하자(실제 임베딩이 아닌 설명용 좌표다).


| 문장             | 벡터      |
| -------------- | ------- |
| A: "우주 비행체 추진" | (3, 4)  |
| B: "로켓 엔진 추력"  | (2, 5)  |
| C: "항공 예약 오류"  | (5, −1) |


[코사인 유사도](https://sbert.net/docs/sentence_transformer/usage/semantic_textual_similarity.html)는 두 벡터의 내적을 각 크기의 곱으로 나눈 값이다. 결과는 −1에서 1 사이이며, 1에 가까울수록 같은 방향을 가리킨다.


```javascript
|A| = √(9+16) = 5,  |B| = √(4+25) ≈ 5.385,  |C| = √(25+1) ≈ 5.099

cos(A, B) = (3×2 + 4×5) / (5 × 5.385) = 26 / 26.93 ≈ 0.966
cos(A, C) = (3×5 + 4×(−1)) / (5 × 5.099) = 11 / 25.50 ≈ 0.431
cos(B, C) = (2×5 + 5×(−1)) / (5.385 × 5.099) = 5 / 27.46 ≈ 0.182
```


A와 B는 0.97에 가까워 거의 같은 방향을 가리키고, B와 C는 0.18로 방향이 많이 다르다. 0이 아닌 벡터의 크기 차이는 정규화되며, 원문 길이는 임베딩 방향에 영향을 줄 수 있다. 영벡터는 분모가 0이므로 별도의 처리가 필요했다. 코사인 유사도는 벡터 사이의 각도를 비교한다.

## 해시 함수로 벡터를 만드는 방법


문장을 벡터로 바꾸는 가장 단순한 접근 중 하나는 해시 함수를 쓰는 것이다. 여기서는 아래의 설명용 규칙을 정해 두었다. 해시 표현의 동작을 설명하기 위해 구성한 규칙이다.

1. 입력 문장을 토큰으로 분리한다.
2. 각 토큰의 SHA-256 해시를 구한다.
3. 해시의 처음 4바이트로 384차원 벡터의 위치(인덱스)를 결정한다(`해시값 mod 384`).
4. 5번째 바이트로 양수, 음수 부호를 정한다.
5. 같은 토큰이 여러 번 나오면 `1 + log(빈도)`로 가중치를 준다.
6. 모든 토큰 처리 후 L2 정규화로 단위 벡터를 만든다.

핵심 특징은 학습 과정이 전혀 없다는 것이다. "로켓"이라는 단어의 SHA-256 해시값은 어떤 데이터를 보았든 항상 동일하다. 따라서 "로켓"과 "발사체"는 서로 다른 해시값을 갖고, 벡터 공간에서 가까워질 근거가 없다.


같은 토큰은 같은 위치에 기여하지만 다른 토큰도 우연히 같은 위치로 들어갈 수 있다. 이 해시 충돌은 의미 관계를 학습한 결과와는 다르다.


## 학습 임베딩이 다른 점


학습 기반 임베딩은 대량의 텍스트를 보고 "비슷한 맥락에 등장하는 단어는 비슷한 벡터를 갖도록" 가중치를 조정한다. 2013년 Mikolov 등이 발표한 [word2vec](https://arxiv.org/abs/1301.3781)은 단어 표현을 학습하는 대표적인 초기 신경망 접근 중 하나로 읽을 수 있다.


이 논문은 단어 벡터 연구의 흐름에서 Skip-gram 학습 방식을 제시했다. Skip-gram 모델은 한 단어를 입력으로 주변 단어를 예측하는 과정을 반복하면서, "king − man + woman ≈ queen" 같은 관계가 벡터 산술로 표현되는 공간을 만들어 낸다.


단어 수준에서 문장 수준으로 확장한 것이 [Sentence-BERT](https://arxiv.org/abs/1908.10084)(Reimers & Gurevych, 2019)다. BERT 위에 시아미즈 네트워크를 올려 문장 전체를 하나의 벡터로 압축하고, 의미가 비슷한 문장 쌍의 코사인 유사도가 높아지도록 학습시킨다.


이렇게 만든 벡터에서는 "로켓 추진 원리"와 "발사체 엔진 작동"이 가까운 좌표에 놓일 수 있다. 이런 근접성을 학습으로 얻으려는 접근이지만, 특정 문장 쌍이 실제로 가까운지는 사용할 모델에서 확인해야 했다.

## 같은 문장 쌍에서 두 방식의 차이가 드러나는 지점


해시 벡터와 학습 임베딩의 차이는 동의어나 문맥이 개입할 때 선명해진다.


| 확인할 입력          | 해시 표현에서 점검할 것   | 학습 표현에서 점검할 것         |
| --------------- | --------------- | --------------------- |
| 같은 문장 두 번       | 동일 전처리와 해시 규칙인지 | 동일 모델과 입력 조건인지        |
| 추진 시스템 / 엔진 장치  | 공유 토큰과 해시 충돌    | 동의어를 가까이 두는지 실제 비교    |
| 사과 재배 / 사과하는 방법 | 같은 토큰의 겹침       | 서로 다른 문맥을 구분하는지 실제 비교 |


이 표는 검증할 질문을 정리한 것이다. 같은 모델에서 동일하게 계산한 0이 아닌 벡터는 자기 자신과 코사인 유사도 1이지만, 서로 다른 문장의 점수는 학습 데이터, 전처리, 문맥에 따라 달라진다. 의미 검색이라는 이름만으로 동의어나 다의어를 항상 잘 처리한다고 판단할 수는 없었다.


해시 표현은 외부 모델 로딩 없이 계산할 수 있어 단순한 비교의 출발점이 된다. 학습 임베딩은 더 넓은 표현 관계를 반영할 여지가 있는 대신 모델 로딩, 메모리, 도메인 검증 비용이 따른다. 두 방식의 선택 조건을 벡터 길이와 좌표 생성 방식으로 나누어 정리했다.


## 추가로 정리할 내용


벡터로 문장을 비교하는 흐름을 정리한 뒤, 정확히 “추진”이라는 단어가 들어간 문서를 찾는 방법도 함께 볼 필요가 있었다. 다음에는 역색인과 BM25의 단어 기반 검색을 살펴본다. 이어 코사인 유사도(−1~1)와 BM25 점수(0~수십)처럼 단위가 다른 결과를 합치는 기준으로 연결한다.
