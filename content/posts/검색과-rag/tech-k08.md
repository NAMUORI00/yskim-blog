## 두 검색기의 점수를 나란히 놓으면 생기는 문제


벡터 검색과 BM25 결과를 합치는 방법으로 RRF를 정리했다. 두 검색기의 점수는 척도가 달라 단순 합산에서 한쪽이 크게 반영될 수 있다. 점수 대신 순위를 사용하는 계산을 문서 네 개의 예제로 따라갔다.


벡터 검색이 문서 A에 0.95점을 매기고 BM25가 문서 B에 3.41점을 매겼다고 해 보자. 어느 쪽이 더 관련 있는지 판단하려면 0.95와 3.41을 비교해야 하는데, 이 둘은 서로 다른 단위에서 나온 숫자다.


점수를 0~1로 정규화하는 방법도 있지만, 각 검색기의 점수 분포가 질의마다 달라지기 때문에 어떤 정규화가 적절한지 평가해야 한다. 점수를 보정해 결합하는 방법도 가능하지만, 이 글에서는 점수 분포를 직접 맞추지 않는 대안으로 순위를 살펴봤다.


검색 채널이 늘어나도 같은 문제가 이어진다. 이미지 벡터, 그래프 기반 검색 등 채널이 늘어날수록 점수 체계가 제각각이 되고, 정규화의 난이도도 함께 올라간다.

## 점수 대신 순위를 쓰자는 아이디어


RRF는 원래 점수의 크기를 사용하지 않고 각 목록의 순위를 결합한다. 벡터 검색에서 1등인 문서와 BM25에서 1등인 문서는 각 기준의 최상위 결과로 취급된다. 원래 점수가 0.95와 3.41이어도 결합에는 “1등”이라는 위치만 쓰는 방식이다.


2009년 Cormack, Clarke, Büttcher가 SIGIR에서 발표한 [Reciprocal Rank Fusion(RRF)](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)이 이 아이디어를 공식으로 정리한 것이다.


논문의 비교 결과는 해당 실험 조건에 속한다. 여기서는 성능 우위를 미리 가정하지 않고 순위 목록에서 결합 점수를 계산하는 과정부터 정리했다.


## RRF 공식으로 순위 합산하기


RRF 점수는 각 검색기에서 해당 문서의 순위에 반비례하는 값을 더한 것이다.


```javascript
RRFscore(d) = Σ  1 / (k + r(d))
```

- **d**: 문서
- **r(d)**: 각 검색기에서 문서 d의 순위 (1부터 시작)
- **k**: 상수 (원 논문 기준 60)
- **Σ**: 모든 검색기에 대해 합산

구체적인 예제로 따라가 보자. 두 검색기가 같은 질의에 대해 다음 결과를 반환했다.


**벡터 검색 결과:**


| 순위 | 문서 | 코사인 유사도 |
| -- | -- | ------- |
| 1  | A  | 0.95    |
| 2  | C  | 0.82    |
| 3  | B  | 0.71    |


**BM25 검색 결과:**


| 순위 | 문서 | BM25 점수 |
| -- | -- | ------- |
| 1  | B  | 2.8     |
| 2  | A  | 1.9     |
| 3  | D  | 1.2     |


k=60으로 각 문서의 RRF 점수를 계산한다. 원래 점수(0.95, 2.8 등)는 사용하지 않고 순위만 쓴다.


```javascript
Doc A: 1/(60+1) + 1/(60+2) = 1/61 + 1/62 ≈ 0.01639 + 0.01613 = 0.03252
Doc B: 1/(60+3) + 1/(60+1) = 1/63 + 1/61 ≈ 0.01587 + 0.01639 = 0.03226
Doc C: 1/(60+2)            = 1/62         ≈ 0.01613
Doc D:            1/(60+3) = 1/63         ≈ 0.01587
```


**최종 순위: A(0.03252) > B(0.03226) > C(0.01613) > D(0.01587)**


문서 A가 종합 1위다. BM25에서는 B가 1등이었지만, 벡터 검색에서 A가 1등, B가 3등이었던 차이가 최종 결과를 갈랐다. A는 두 검색기 모두에서 상위권(1등, 2등)이었고, B는 한쪽에서 3등이었기 때문이다. 원래 점수의 절대값(0.95 vs 2.8)은 계산에 전혀 관여하지 않았다는 점이 RRF의 핵심이다.


## 한쪽에만 등장하는 문서의 처리


위 예제에서 문서 C는 벡터 검색에만, 문서 D는 BM25에만 등장한다. 나머지 검색기에는 결과가 없으므로 해당 채널의 기여분은 0이다.


C의 RRF 점수(0.01613)와 D의 RRF 점수(0.01587)의 차이는 순전히 순위에서 온다. C는 벡터 검색 2등, D는 BM25 3등이었으므로, 2등의 1/(60+2)가 3등의 1/(60+3)보다 근소하게 크다.


한 채널에만 있는 문서는 그 채널의 기여값을 받고, 여러 채널에 나온 문서는 각각의 기여값을 더한다. 별도의 누락 보정 없이 반복 등장 여부가 점수에 반영되는 구조다. 여러 검색기가 같은 문서를 올리는 경우를 이 합산 과정으로 읽을 수 있었다.

## 상수 k가 결과에 미치는 영향


공식의 k는 순위 차이가 점수에 미치는 영향을 조절한다. k가 크면 분모가 커져 1등과 3등의 점수 차이가 줄어들고, k가 작으면 상위 순위에 점수가 집중된다.


위 예제에서 k=10으로 바꿔 보자.


```javascript
Doc A (k=10): 1/11 + 1/12 ≈ 0.0909 + 0.0833 = 0.1742
Doc B (k=10): 1/13 + 1/11 ≈ 0.0769 + 0.0909 = 0.1678
```


k=60일 때 A와 B의 차이는 0.03252 − 0.03226 = 0.00026이었다. k=10에서는 0.1742 − 0.1678 = 0.0064로, 차이가 약 25배 벌어진다.


k가 작을수록 순위 한 칸의 차이가 점수에 크게 반영되므로 상위권 문서 사이의 구분이 선명해지고, 같은 k에서는 순위가 뒤로 갈수록 인접 순위의 기여값 차이가 작아진다. k를 바꾼 두 점수의 절대 차이만으로 검색 품질이 좋아졌다고 해석할 수는 없다.


원 논문의 k=60을 비교 출발점으로 두고, 대상 데이터에서 적절한 값을 평가한다. 결과 목록 길이와 채널 수가 바뀌면 여러 채널에 반복 등장하는 문서의 이점도 달라진다. 조정에 쓴 질문과 최종 평가 질문을 분리해서 비교할 필요가 있었다.


순위만 남기면서 잃는 정보도 있었다. 1위와 2위의 원래 점수 차이가 매우 크든 거의 없든 RRF는 같은 순위 차이로 읽는다. 동일 문서가 한 채널에서 중복 반환되면 먼저 식별자로 정리하고, 동점의 처리 규칙도 고정해야 재실행 결과를 비교할 수 있다.


## 추가로 정리할 내용


RRF는 검색기별 점수 분포를 직접 맞추지 않고도 순위를 합칠 수 있다. 다만 검색기들의 품질 차이가 큰 경우에도 동일한 가중치를 둘지는 별도의 비교가 필요하다.


채널별 가중치를 다르게 주는 가중 RRF(weighted RRF)와 가중치 선택에 사용할 평가 기준은 후속 주제로 남겼다.
