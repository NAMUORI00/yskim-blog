## 두 검색기의 점수를 바로 더할 수 없는 이유


앞선 글에서 의미 유사도를 계산하는 벡터 검색과 단어 빈도 기반의 BM25 검색을 각각 다뤘다. 두 검색기를 함께 쓰면 문서의 의미와 정확한 키워드를 동시에 잡을 수 있지만, 두 결과를 하나의 목록으로 합치는 단계에서 점수 척도 문제가 생긴다.


예를 들어 같은 질의에 대해 벡터 검색이 문서 A에 코사인 유사도 0.95점을 매기고, BM25가 문서 B에 3.41점을 매겼다고 해 보자. 어느 문서가 질의와 더 관련 있는지 판단하려면 0.95와 3.41을 비교해야 하는데, 두 숫자는 계산 방식과 범위가 전혀 다르다. 코사인 유사도는 -1에서 1 사이의 값이지만 BM25 점수는 상한이 따로 없어, 두 점수를 단순 합산하면 숫자가 큰 BM25 쪽이 결과를 크게 좌우한다.


각 검색기의 점수를 0~1 범위로 정규화한 뒤 더하는 방법도 있다. 하지만 질의마다 반환되는 점수 분포가 달라지기 때문에 어떤 정규화 방식이 적절한지 별도로 평가해야 한다. 여기에 이미지 벡터나 그래프 기반 검색까지 검색 채널이 늘어나면 제각각인 점수 체계를 맞추기는 더 까다로워진다. 이 글에서는 점수 분포를 직접 보정하는 대신 각 검색기가 매긴 순위만 뽑아 결합하는 방법을 살펴본다.


![질의에 대해 벡터 검색의 코사인 유사도와 BM25 검색 점수는 단위가 달라 직접 더할 수 없으므로 순위로 변환해 결합함을 나타낸 도식](/images/notion/tech-k08/image-1.png)


그림 1. 서로 다른 점수 척도를 가진 두 검색 결과를 그대로 더하지 않고 순위로 변환해 결합하는 과정(개념도).


## 점수 대신 순위를 합치는 RRF


**Reciprocal Rank Fusion**(RRF)은 원래 점수의 크기를 버리고 각 검색 결과 목록에서의 순위만 이용해 점수를 다시 매긴다. 2009년 Cormack, Clarke, Büttcher가 SIGIR에서 발표한 [Reciprocal Rank Fusion(RRF)](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf) 논문에서 제안한 공식으로, 논문의 비교 결과는 해당 실험 조건에 속하므로 여기서는 성능 우위를 미리 가정하지 않고 결합 점수를 계산하는 과정부터 정리한다. 벡터 검색 1위 문서의 점수가 0.95이고 BM25 1위 문서의 점수가 3.41이더라도, 결합 단계에서는 두 문서 모두 각 기준에서 1위를 차지했다는 위치 정보만 사용한다.


RRF 점수는 각 검색기에서 문서가 받은 순위에 상수 `k`를 더한 뒤, 그 역수를 모든 검색기에 대해 합산해 구한다.


```plain text
RRFscore(d) = Σ  1 / (k + r(d))
```

- `d`: 문서
- `r(d)`: 각 검색기에서 문서 `d`의 순위 (1부터 시작)
- `k`: 순위 차이의 반영 폭을 조절하는 상수 (원 논문 기준 60)
- `Σ`: 모든 검색기에 대해 합산

문서 네 개(A, B, C, D)로 계산 과정을 따라가 보자. 같은 질의에 대해 두 검색기가 다음과 같은 상위 3개 결과를 반환했다고 가정한다.


### 벡터 검색 결과


| 순위 | 문서 | 코사인 유사도 |
| -- | -- | ------- |
| 1  | A  | 0.95    |
| 2  | C  | 0.82    |
| 3  | B  | 0.71    |


### BM25 검색 결과


| 순위 | 문서 | BM25 점수 |
| -- | -- | ------- |
| 1  | B  | 2.8     |
| 2  | A  | 1.9     |
| 3  | D  | 1.2     |


원 논문과 같이 `k=60`으로 두고 각 문서의 RRF 점수를 계산한다. 원래 점수(0.95, 2.8 등)는 쓰지 않고 1, 2, 3위라는 순위만 대입한다.


```plain text
Doc A: 1/(60+1) + 1/(60+2) = 1/61 + 1/62 ≈ 0.01639 + 0.01613 = 0.03252
Doc B: 1/(60+3) + 1/(60+1) = 1/63 + 1/61 ≈ 0.01587 + 0.01639 = 0.03226
Doc C: 1/(60+2)            = 1/62         ≈ 0.01613
Doc D:            1/(60+3) = 1/63         ≈ 0.01587
```


합산 결과에 따른 최종 순위는 `A(0.03252) > B(0.03226) > C(0.01613) > D(0.01587)`이다.


BM25에서는 문서 B가 2.8점으로 1위였지만 종합 순위에서는 문서 A가 1위가 되었다. 원래 점수의 절대값(0.95와 2.8)은 계산에 관여하지 않고, 문서 A는 두 검색기에서 1위와 2위로 모두 상위권에 오른 반면 문서 B는 벡터 검색에서 3위로 밀렸던 차이가 결과를 갈랐다.


## 한쪽 검색기에만 나온 문서의 처리


위 예제에서 문서 C는 벡터 검색에만, 문서 D는 BM25에만 등장한다. 나머지 검색기 목록에는 해당 문서가 없으므로 그 채널에서 얻는 점수는 0이다.


따라서 문서 C의 RRF 점수(0.01613)와 문서 D의 RRF 점수(0.01587) 차이는 온전히 각 채널에서의 순위에서 나온다. 문서 C는 벡터 검색 2위여서 `1/(60+2)`를 받고, 문서 D는 BM25 3위여서 `1/(60+3)`을 받으므로 순위가 한 단계 높았던 C가 D보다 근소하게 앞선다.


이처럼 RRF에서는 누락된 채널을 보정하는 별도 계산이 필요 없다. 한 채널에만 나온 문서는 그 채널의 점수만 받고, 여러 채널에 동시에 등장한 문서(A, B)는 각 채널의 점수가 더해져 자연스럽게 상위권으로 올라간다.


![벡터 검색과 BM25 순위표에서 문서 A, B, C, D의 역순위 점수를 합산해 A, B, C, D 순서로 최종 순위가 결정되는 계산 과정 도식](/images/notion/tech-k08/image-2.png)


그림 2. 문서 네 개 예제에서 양쪽 채널에 등장한 문서(A, B)와 단일 채널에 등장한 문서(C, D)의 RRF 점수를 합산해 정렬하는 과정.


## 상수 k의 역할과 순위 결합 시 고려할 점


공식의 상수 `k`는 순위 차이가 최종 점수에 미치는 영향을 조절한다. `k`가 크면 분모(`k + r(d)`)가 커져 1위와 3위의 점수 차이가 줄어들고, `k`가 작으면 상위 순위에 점수가 집중된다.


앞선 예제에서 `k=10`으로 바꾸면 문서 A와 B의 점수는 다음과 같이 달라진다.


```plain text
Doc A (k=10): 1/11 + 1/12 ≈ 0.0909 + 0.0833 = 0.1742
Doc B (k=10): 1/13 + 1/11 ≈ 0.0769 + 0.0909 = 0.1678
```


`k=60`일 때 문서 A와 B의 차이는 `0.03252 − 0.03226 = 0.00026`이었다. 반면 `k=10`에서는 `0.1742 − 0.1678 = 0.0064`가 되어 두 문서의 점수 차이가 약 25배로 벌어진다.


![k가 10일 때는 문서 A와 B의 점수 차이가 0.0064로 크고, k가 60일 때는 0.00026으로 완만해지는 비교 도식](/images/notion/tech-k08/image-3.png)


그림 3. 상수 k를 10과 60으로 두었을 때 문서 A와 문서 B의 RRF 점수 차이 비교.


`k`가 작을수록 순위 한 칸의 차이가 점수에 크게 반영되어 상위권 문서 사이의 구분이 뚜렷해지고, 같은 `k` 안에서는 순위가 뒤로 갈수록 인접한 순위 사이의 점수 차이가 작아진다. 다만 `k`를 바꿔 두 문서의 점수 절대 차이가 커졌다는 사실만으로 검색 품질이 좋아졌다고 볼 수는 없다.


실제로 적용할 때는 원 논문의 `k=60`을 비교 출발점으로 삼고 대상 데이터에서 적절한 값을 평가한다. 검색기마다 반환하는 목록 길이와 결합하는 채널 수가 바뀌면 여러 채널에 반복 등장하는 문서가 얻는 이점도 달라지므로, `k`를 조정하는 데 쓴 질문과 최종 평가 질문은 분리해서 비교해야 한다.


점수를 버리고 순위만 남기면서 잃는 정보도 있다. 1위와 2위의 원래 점수 차이가 아주 크든 거의 없든 RRF는 똑같이 순위 한 칸 차이로만 처리한다. 또한 한 검색기 안에서 같은 문서가 중복으로 반환되면 결합 전에 문서 식별자로 먼저 정리해야 하고, 합산 점수가 같을 때의 동점 처리 규칙도 고정해야 재실행 결과를 일관되게 비교할 수 있다.


RRF는 검색기별 점수 분포를 직접 맞추지 않고도 여러 순위 목록을 합칠 수 있다. 다만 결합하는 검색기들의 품질 차이가 클 때도 모든 채널에 같은 비중을 둘지는 별도로 따져 봐야 한다. 채널별 가중치를 다르게 주는 가중 RRF(weighted RRF)와 중복 문서 처리, 가중치 선택에 사용할 평가 기준은 이어지는 글에서 다룬다.
