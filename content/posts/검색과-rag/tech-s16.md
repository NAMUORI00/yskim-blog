## 호출 순서를 정하기 전에 입력부터 확인하기


두 카메라의 입력을 가정해 입력 확인, 모델 선택, 호출, 후속 처리의 순서를 정리했다. 파일을 열지 못한 경우와 필요한 장면이 없는 경우, 모델 호출이 실패한 경우를 각각 나누었다.


입력 가용성과 내용 판단, 호출 결과를 구분하면 다음에 시도할 작업도 달라진다. 라우팅은 이 상태를 받아 호출 경로를 고르는 과정으로 읽었다.


## 입력 누락과 영상 품질의 구분


설명용 질문을 “사람이 문을 통과했는가”로 잡았다. A 카메라는 파일을 읽을 수 있고 문이 보인다. B는 파일 경로가 있지만 디코딩에 실패했다. B는 평가할 영상 입력을 만들지 못한 상태다.


A가 질문에 답할 충분한 구간을 보여 주면 한 시점만으로 판단하는 정책을 생각할 수 있다. 반면 질문이 “문을 지난 사람이 반대편 통로로 나왔는가”라면 B의 구간이 필요할 수 있다. 사용 가능한 입력 수만 세어서 답변 여부를 정할 수 없는 이유다. 필요한 시점과 시간 범위는 질문에 따라 달라진다.

그림 1. 입력 누락을 먼저 기록하고 질문에 필요한 범위를 확인하는 설명용 분기. 특정 프로젝트의 자동 복구 구현을 나타내지는 않는다. 출처: 본문의 두 카메라 예제로 직접 구성.


파일 존재, 디코딩, 요청 구간 확보, 질문 관련성을 차례로 확인하는 흐름으로 놓았다. 어느 단계까지 통과했는지를 남기면 입력 누락의 위치를 더 구체적으로 설명할 수 있다.


## 첫 호출 이후의 네 갈래


모델 A를 호출했을 때 결과를 네 종류로 나누어 보았다. 충분한 근거와 함께 답변한 경우, 정상 응답했지만 근거가 부족한 경우, 요청 시간이 초과된 경우, 응답 형식이 계약과 맞지 않는 경우다. 뒤의 세 경우를 모두 “답변이 틀림”으로 세면 서비스 오류와 판단 오류를 섞게 된다.


근거 부족에는 다른 시점 추가를, 시간 초과에는 남은 시간과 중복 실행 여부 확인을 대응시켰다. 형식 오류에는 제한된 파싱 복구나 다음 호출을 비교할 수 있다. 대체 경로가 끝없이 이어지지 않도록 호출 횟수와 종료 조건도 함께 두는 예제다.


[GRACE](https://arxiv.org/abs/2601.04525)와 [SURE-RAG](https://arxiv.org/abs/2605.03534)는 근거 충분성과 보류를 다루는 연구다. 이 연구들이 다루는 내용 판단을 서비스의 접속 실패와 같은 사건으로 보지는 않았다. 논문의 평가 조건을 그대로 영상 시스템의 운영 결과로 옮길 수도 없다.

## 평균 비용과 개별 요청 지연


계산용으로 라우팅 0.2초, 첫 호출 2초, 추가 호출 5초를 가정했다. 전체 요청의 30%에서 추가 호출이 필요하고 대기, 재시도는 없다고 놓으면 순차 경로의 평균 시간은 0.2 + 2 + 0.3×5 = 3.7초다. 모두 두 모델을 순차 호출하면 같은 가정에서 7.2초다.


흐름 설명을 위해 정한 예시 값이다. 특히 두 호출이 모두 필요한 요청은 여전히 7.2초 경로를 지난다. 평균이 줄었다고 상위 지연 구간까지 같은 비율로 줄었다고 말할 수 없다. 병렬 호출은 이상적인 독립 자원 조건에서 약 0.2 + max(2, 5) = 5.2초로 끝날 수 있지만 두 호출 비용을 모두 지불하고, 실제 자원을 공유하면 지연도 달라진다.


비용 단위를 첫 호출 1, 추가 호출 3으로 두면 선택 호출의 기대비용은 1 + 0.3×3 = 1.9다. 이 계산에서도 시간 초과된 요청의 과금, 재시도, 전처리와 저장 비용은 제외했다. 호출이 실패했다는 이유만으로 비용을 0으로 놓으면 비교가 낙관적으로 바뀐다.


## 비교 표에 남겨야 할 분모


정책 비교의 분모는 동일한 전체 요청 집합으로 두었다. 입력 누락과 호출 실패를 제외한 답변만 비교하면 선택 과정의 영향을 놓칠 수 있다. 답변 비율, 답변한 경우의 오류율, 전체 실패율을 함께 읽는 기준이다.


MV-EviRAG의 [README](https://github.com/NAMUORI00/RoleSep-VQA/blob/775b34eafca5db8914522ac7a582a1d841a63773/README.md)는 생성 전 가용성 판단, 생성 후 근거 판단, 답변 확신도에 따른 선택을 구분한다.


저장소 접근 권한이 필요하다. 세 판단을 호출 경로로 이해하기 위해 구성한 시간 계산 예제다.


추가 호출 비율의 변화는 입력 누락, 충분성 기준, 첫 모델 오류로 나누어 살펴볼 후속 항목이다. 어떤 조건에서 경로가 바뀌었는지 기록하면 비용 변화의 원인도 함께 비교할 수 있다.
