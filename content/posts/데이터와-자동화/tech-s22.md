설명용 다섯 행을 CSV에서 JSON으로 옮기며 식별자 대응과 결측 처리를 정리했다. 빈칸과 0의 차이, 같은 이름을 가진 대상의 연결 기준을 나누고 기준 시각, 단위, 원본 식별자를 함께 따라갔다.


행, 열, 키와 결측값 개념을 바탕으로 예제를 구성했다. 날짜와 단위는 표 안에서 비교하고, 실제 수집기의 재시도 경로는 프로젝트 글에 연결했다.


## 데이터 한 행의 기준


아래 값은 변환 규칙 설명을 위해 구성한 예시다. 두 출처가 같은 관측 대상을 서로 다른 식별자로 표현하는 상황을 만든 예제다. 기준 시각과 수집 시각은 모두 같은 시간대를 쓴다고 가정한다.


| 행 | 출처와 원본 ID | 기준 시각 | 수집 시각 | 원본 값 | 단위 |
| - | --------- | ----- | ----- | ---- | -- |
| 1 | A·0017    | 09:00 | 09:05 | 1.20 | m  |
| 2 | A·0017    | 09:00 | 09:10 | 1.20 | m  |
| 3 | B·X9      | 09:00 | 09:06 | 120  | cm |
| 4 | A·0017    | 10:00 | 10:05 | 빈칸   | m  |
| 5 | A·0017    | 11:00 | 11:05 | 0    | m  |


1행과 2행은 수집 시각만 다르다. 출처, 원본 ID, 기준 시각, 관측 항목을 키로 삼는다면 같은 관측의 중복 수집 후보가 된다. 하지만 원문이 수정될 수 있는 자료라면 내용 해시나 원본 버전도 비교해야 한다. 같은 주소에서 다시 받았다는 사실만으로 같은 내용이라고 처리할 수는 없다.


3행은 A의 0017과 B의 X9가 같은 대상이라는 별도 대응표가 있을 때에만 연결할 수 있다. 단위를 바꾸면 120cm가 1.20m가 되지만, 숫자가 같다는 이유로 대상까지 같다고 판단하면 순서가 뒤집힌다. 식별자 대응과 단위 변환은 서로 다른 근거를 요구한다.

## 결측값과 숫자 0의 변환


4행의 빈칸은 이 예제에서 관측값을 받지 못했다는 뜻으로 정한다. 5행의 0은 실제로 받은 값이다. 평균을 계산한다고 둘 다 0으로 채우면 자료가 없다는 사건이 값이 작다는 사건으로 바뀐다. 결과에는 값뿐 아니라 missing_reason 같은 설명을 남길 수 있다. 원본 시스템에서 빈칸의 뜻을 정하지 않았다면 우선 ‘의미 미확인’으로 유지해야 한다.


0017은 숫자처럼 보이지만 여기서는 식별자이므로 문자열로 유지한다. 숫자 17로 변환하면 앞의 0이 사라지고 다시 원본에 대응할 때 정보가 부족해진다.


[pandas read_csv 문서](https://pandas.pydata.org/docs/reference/api/pandas.read_csv.html)의 dtype, na_values, keep_default_na 같은 옵션은 이런 결정을 명시하는 데 쓰인다. 기본 추론에 맡기기 전에 어느 열이 계산값이고 어느 열이 코드인지부터 정할 필요가 있다.


```json
{
  "source": "A",
  "source_id": "0017",
  "observed_at": "2026-09-15T10:00:00+09:00",
  "collected_at": "2026-09-15T10:05:00+09:00",
  "value": null,
  "unit": "m",
  "missing_reason": "not_received",
  "raw_value": ""
}
```


이 JSON은 변환 계약을 설명하는 예제다. 날짜 전용 값에 임의의 자정 시각을 부여하거나 시간대 없는 값에 오프셋을 덧붙이는 변환은 포함하지 않았다.


또한 [JSON 표준 RFC 8259](https://www.rfc-editor.org/rfc/rfc8259)는 NaN이나 Infinity를 숫자로 허용하지 않는다. 분석 도구 내부의 결측 표현을 API에 내보내기 전에 null 등 약속한 형식으로 바꾸는 단계가 필요하다.


## 파일 형식과 스키마 정의


FASTAPI_PANDAS_CSV2JSON의 [표 데이터 변환 코드](https://github.com/NAMUORI00/FASTAPI_PANDAS_CSV2JSON/blob/ee7ec277a5321f84da4a3424f5e41a270129fffe/main.py)에는 csv.DictReader로 읽은 행을 JSON 배열로 쓰는 함수가 있다.


처음에는 문자열을 옮기고 이후 pandas에서 읽어 열 이름을 바꾸는 흐름이다. 변환이라는 이름 아래 여러 단계가 이어져 숫자, 날짜 해석 시점을 따로 읽었다.


JSON 파일은 요청 처리에 앞선 모듈 로딩 시점에 읽는다. 원본 파일의 변경을 반영하려면 데이터프레임을 다시 읽어야 한다. 코드의 데이터 생명주기에서 확인한 갱신 조건이다.

갱신 기록은 새 대상, 수정된 관측, 사라진 행, 해석 실패로 나누는 형식을 생각해 보았다. 사라진 행도 삭제와 수집 실패를 구분해야 처리 범위를 정할 수 있다. 원본 버전과 변환 규칙을 함께 남기면 출력의 생성 경로를 다시 추적할 수 있다.


URL, 내용 해시, 관측 키에 따른 중복 제거 차이는 후속 비교 항목으로 남겼다. 같은 페이지의 수정 이력을 보관할지 최신 상태만 유지할지에 따라 키의 역할이 달라진다.
