## 파일 읽기 요청과 반환값


파일 읽기 호출을 따라 사용자 프로그램과 커널의 역할을 정리했다. `read(fd, buf, 128)`로 128바이트를 요청해도 파일 끝에 50바이트만 남았다면 반환 길이는 그만큼이다. 반환값 0은 파일 끝을, -1은 오류를 확인할 단서가 된다.


[read(2) 명세](https://man7.org/linux/man-pages/man2/read.2.html)


프로그램은 파일 번호와 버퍼 주소를 전달하고, 커널은 열려 있는 파일 상태와 읽기 조건을 확인한다. 보호 경계를 이 요청의 입력과 검사 과정에 연결해 살펴봤다.


## 주소가 놓인 영역과 실행 권한


사용자 영역은 프로그램 코드, 힙, 스택 등이 놓이는 가상 주소 공간이고, 사용자 모드는 제한된 권한으로 코드를 실행하는 상태를 가리킨다. 사용자 영역은 주소 범위, 사용자 모드는 실행 권한을 설명하는 용어다. 여기서는 일반적인 x86-64 리눅스 프로세스와 파일 읽기를 예로 잡았다.


프로세스 A와 B의 `0x400000`은 각 프로세스의 페이지 테이블에 따라 해석된다. 각 프로세스의 주소 변환을 거쳐 다른 메모리에 연결되거나, 한쪽에서는 매핑이 없을 수 있다.


같은 프로세스의 스레드는 주소 공간을 공유하지만 각각 실행 위치와 스택 같은 상태를 따로 갖는다. 공유 힙을 볼 수 있다는 사실만으로 접근 순서까지 맞춰지는 것은 아니어서, 동시에 읽고 쓸 때는 동기화가 별도로 필요하다.


CPU의 메모리 접근 검사는 사용자 코드가 커널 전용 페이지를 평범한 읽기 명령으로 참조하는 것을 제한한다. 다만 이를 운영체제 전체의 무결성이 무조건 보장된다는 말로 넓힐 수는 없다. 페이지 설정, 커널 코드, 하드웨어의 동작 조건도 보호의 일부다.


리눅스의 커널 주소 배치는 4단계, 5단계 페이지 테이블에서 다르게 설명된다. PTI 환경에서는 사용자 실행용 테이블에 커널 전체를 매핑하지 않고 진입에 필요한 일부를 남긴다. 주소 배치도 실행 환경에 따라 읽을 조건이었다.


따라서 “모든 프로세스에 커널 메모리가 항상 전부 매핑된다”는 그림은 현재 구성을 설명하기에 부족하다. [주소 배치](https://docs.kernel.org/arch/x86/x86_64/mm.html), [PTI 문서](https://docs.kernel.org/arch/x86/pti.html).

## 진입과 복귀 사이에서 확인하는 것


x86-64의 전형적인 경로에서는 C 라이브러리 래퍼가 인자를 전달하고 `syscall` 명령을 통해 커널 진입점으로 넘어간다. 커널은 파일 디스크립터가 가리키는 객체와 읽기 조건을 확인하고, 해당 객체의 읽기 구현으로 요청을 보낸다. 같은 `read`라도 일반 파일, 파이프, 장치 파일의 동작을 모두 디스크 읽기로 설명할 수는 없다.


사용자 버퍼로 데이터를 옮기는 경로에서는 접근 가능한 주소인지도 확인해야 한다. 커널의 사용자 메모리 복사 도우미는 사전 주소 범위 검사와 실제 복사 과정의 접근 오류를 함께 처리한다. 매핑과 접근 가능성 때문에 복사 도중에도 문제가 생길 수 있다.


반환값이 50이라면 읽기 대상으로 삼을 범위는 `buf[0]`부터 `buf[49]`까지다. 나머지 78바이트가 이번 호출로 채워졌다고 가정하면 이전 값이나 초기화하지 않은 내용을 섞어 읽게 된다. 128바이트를 반드시 모아야 하는 형식이라면, 상위 코드에서 누적 길이와 파일 끝, 오류를 함께 처리해야 한다.

## 호출 횟수를 줄이려는 이유


작은 읽기를 반복하면 커널 진입과 인자 처리 같은 비용도 반복된다. 성공적으로 1바이트씩 128번 읽는 경우와, 한 번의 호출로 128바이트를 받는 경우는 전달량이 같아도 호출 횟수가 다르다. 사용자 모드와 커널 모드를 오가는 일은 반드시 다른 프로세스로 실행을 넘기는 문맥 교환과 같지는 않다. 다만 읽기가 대기 상태에 들어가면 스케줄링이 추가될 수 있다.


표준 입출력의 버퍼링을 이해할 때도 이 차이가 도움이 됐다. 작은 요청을 버퍼에서 처리하고 실제 읽기는 묶어서 하면 호출 횟수를 줄일 여지가 생긴다. 반면 버퍼 크기, 응답을 기다리는 시간, 장치 특성에 따라 적절한 묶음이 달라진다. 여기서는 호출 수의 차이를 비교했다. CPU별 지연과 속도 변화는 별도 측정 항목이다.


## 후속 검토 범위


파일 읽기에서 주소, 실행 권한, 반환 길이는 서로 다른 조건이었다. 다음에는 사용자 프로그램의 구조체를 커널이 받는 경로에서 길이와 필드 검사가 적용되는 위치를 살펴볼 수 있다. 호출 권한과 입력 유효성의 구분을 후속 내용으로 남겼다.
